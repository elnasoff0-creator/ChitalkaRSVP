# ПРОЧиталка 1.11.112 — локальный журнал Edge TTS

Путь в приложении: **Настройки → Аудио → Диагностика → Показать лог-файл**.

Журнал находится в приватном каталоге приложения `files/diagnostics`.
Активная часть `prochitalka_log_0.txt`, предыдущая `prochitalka_log_1.txt`.
Каждая часть ограничена 512 КиБ. При экспорте создаётся
`prochitalka_log_export.txt`, который отправляется с помощью `FileProvider`.
Все три файла удаляются кнопкой **Очистить**.

## Какие события пишутся

| Категория | События |
|---|---|
| `QUEUE` | очередь Play / prefetch / bulk, выполнение, освобождение, HTTP 429 |
| `POOL` | захват ресурса, повторное использование, возврат, уничтожение |
| `WS` | handshake, open, failure, тип ошибки, тайм-аут отмены |
| `EDGE` | начало/завершение SSML-turn, HTTP 403/429, первый MP3-кадр |
| `PREFETCH` | постановка будущих текстовых диапазонов на подготовку |
| `CACHE` | существующий MP3, сохранение MP3, генерация при отсутствии кэша |
| `PLAYER` | текущий диапазон, реальный старт воспроизведения, ошибка декодирования |
| `LATENCY` | миллисекунды до WebSocket, MP3, первого чтения декодером и первого звука |

Ключи, токены, WebSocket query strings и исходные предложения в файлы не
записываются. Журнал событий не является полным системным `logcat` — Android
не предоставляет приложениям свободный доступ к чужим логам.

## Значение скриншота Quickify

В показанном снимке `MS_TIME_SYNC` выводит `Expected HTTP 101 ... 429 Too
Many Requests`. То есть ошибается **отдельная попытка синхронизации времени**.
Это не свидетельствует о том, что запрос синтеза для текущего предложения
завершился ошибкой. У Quickify возможны открытый WebSocket, работающий MP3-кэш,
фоновый синтез и повторное использование ресурсов, поэтому аудио продолжает играть.

В ПРОЧиталке диагностический журнал явно отделяет
`HTTP 429 from synthesis WebSocket handshake` от событий коррекции времени
после HTTP 403. Сетевые тайминги будут получены на реальном телефоне.

## Проверки

24 существующих и новых QA shell-теста завершились успешно. Тест журнала
проверяет запись событий, скрытие URL, сохранение/ротацию, экспорт и очистку.
APK в текущем окружении не собран; тесты UI являются статическими.
