## HOTFIX — устранение ошибок `:app:compileReleaseJavaWithJavac`

**Источник:** лог GitHub Actions сборки v1.11.131-beta, строка 1246 и 1271 `ReaderActivity.java`.

**Причина:** в двух вызовах `UnifiedReadingProgress.save(Context, String, int, int, String, boolean)` параметр `chapter` требовал текстовое имя (`String`), но передавался `chapterForWord(index)` / `chapterForWord(libraryIndex)`, которые возвращают `int` (порядковый индекс главы). Java не допускает такое неявное преобразование, поэтому release-компиляция завершалась двумя ошибками `incompatible types: int cannot be converted to String`.

**Исправление:** в `ReaderActivity.java` введён `chapterTitleForWord(int): String`. Он сопоставляет индекс слова с оглавлением `actualChapters` и возвращает название главы, а при отсутствии названия — `Глава N` по существующему числовому индексу; если глава не определена, возвращает пустую строку. Оба вызова `UnifiedReadingProgress.save` теперь передают именно этот текст, не изменяя тип и назначение `chapterForWord(int)` для остальных потребителей.

**Регрессионная защита:** добавлен `qa/test_v11131_progress_chapter_types.py`, который извлекает **реальные методы и оба вызова** из `ReaderActivity.java`, компилирует их посредством `javac` с типизированной сигнатурой `save` и проверяет строковые названия глав, смену главы и запасной вариант подписи. Тест включён в `QA_RUN_v1.11.131.py`; локальный прогон — **13/13 PASS**. Отдельно сохранена проверка типизации новых классов на Android API-заглушках.

**Важно:** в исходниках Android-приложения изменён только `ReaderActivity.java`. `versionName=1.11.131-beta`, `versionCode=13100` и вся остальная функциональность сохранены. Полную сборку Android `assembleRelease` в текущей среде выполнить нельзя (отсутствуют Gradle и Android SDK); её должен подтвердить GitHub Actions.

## 2. Единый прогресс книги во всех режимах ReaderActivity

### Суть изменения

Для каждой книги введён **один канонический индекс слова** `book_shared_word:<URI>`. Он используется в режиме обычного чтения, RSVP, курсора, системного TTS и Edge TTS. Общее количество слов для процента: `book_words:<URI>`; название последней главы: `book_shared_chapter:<URI>`.

Процент рассчитывается по позиции в тексте книги: `(индекс слова + 1) × 100 / количество слов` с ограничением 0–100%. **Время MP3, WPM, длительность фрагментов и время прослушивания не определяют общий процент книги.**

### Восстановление и миграция

- При открытии ReaderActivity и при переключении режимов индекс берётся из `UnifiedReadingProgress.read(...)`, а не из отдельных несовпадающих `position:`/`tts_word:`.
- При первом запуске после обновления, если общий индекс ещё отсутствует, миграция учитывает последний активный режим (`reading_mode == 3` для TTS). В дальнейшем все режимы пользуются общей позицией.
- Сохранение позиции во время чтения обновляет общий индекс; при выходе обновляются метаданные произведения в списке Библиотеки, включая главу и процент.
- `MainActivity` при открытии книги и отображении карточки «Продолжить» использует общий индекс, а не устаревший индекс отдельного режима.
- Если общее количество слов ещё неизвестно, неверный знаменатель не формируется и не используется для вычисления процента.

### Фоновая озвучка

- Системный TTS записывает текущую позицию на основе `currentSpokenTtsWord()` и имеющихся синхронизированных временных меток в ходе активного воспроизведения.
- Edge TTS обновляет общий указатель из данных `WordBoundary`/активного клипа через `currentSpeechWord()` при переходах треков и во время работы сервиса в фоне.
- К названию последней главы применяется индекс главы из текста. Статистика сохраняется и после ухода ReaderActivity с экрана.
- Если движок/поток не предоставляет точные временные метки, возможна точность только до начала известного аудиофрагмента; её следует отдельно проверить на устройстве.

**Файлы:** `UnifiedReadingProgress.java` (новый), `ReaderActivity.java`, `MainActivity.java`, `AudioPlaybackService.java`, `EdgeStreamingService.java`.

## 3. Переработанная игровая система «Чтейцо»

### Общая компоновка

- Игра запускается из существующей кнопки с геймпадом рядом с именем питомца.
- По нажатию открывается выбор «Бегун» / «Летун» с указанием ограничений по стадии эволюции.
- Игры работают **внутри той же карточки питомца в `ChteicoActivity`**; отдельный экран больше не открывается.
- При старте обычный питомец, лучи тапов и речевой пузырь временно скрываются; в том же `FrameLayout` создаётся `ChteicoMiniGameView`.
- Контейнер анимированно изменяет высоту с 260 до 305 dp, после выхода восстанавливается обычная карточка и обновлённая игровая статистика.
- Поле светлое `#FFF9F2` с тёмным контуром; персонаж уменьшается до 56/65/73 dp в зависимости от эволюции.
- Внутри игрового поля сверху расположены пауза, счётчик метров и выход. Тап по полю управляет игрой; после столкновения тап запускает новую попытку.
- При уходе Activity в фон игра автоматически переходит на паузу.

### Игра «Бегун»

- Доступна с Чтенчика, включая стадии Чтенец и Чтун.
- Пет бежит в двух векторных кадрах `up/down`; в прыжке используется именно `up`.
- **Ровно два препятствия:** низкая горизонтальная раскрытая книга и высокая вертикальная стоящая книга.
- Короткий тап — прыжок, удержание до ~230 мс усиливает прыжок. Высота ограничена; препятствия движутся по горизонтали и проверяются ограниченными хитбоксами.
- Прежние `runner_best`, `runner_distance`, `runner_games`, `runner_xp` остаются в `ChteicoStore`, поэтому прежние рекорды не теряются при переходе на новую игровую реализацию.

### Игра «Летун»

- Доступна с Чтенца, также доступна Чтуну. На стадии Яйцо и Чтенчик открытие блокируется сообщением о требуемой стадии.
- По принципу Flappy Bird: тап даёт вертикальный импульс вверх, между тапами действует гравитация; столкновение с книгой или границей поля завершает попытку.
- **Один XML-вид стоячей книги** масштабируется по вертикали и служит верхним/нижним препятствием. Параметры прохода и высот изменяются при появлении каждой пары.
- Полёт использует `up` при подъёме и `down` при снижении. Раздельно сохраняются `flyer_best`, `flyer_distance`, `flyer_games`, `flyer_xp`.
- Ограниченный игровой XP из обеих игр учитывается как дополнительный бонус к прогрессу питомца, но не заменяет чтение.

### Удаление растровых игровых файлов

- Удалены **14 старых игровых PNG**: 9 кадров питомца `chteico_game_*`, 5 книг `chteico_book_*`.
- Вместо игровых копий PNG используются **существующие утверждённые XML-векторы питомца** из `ChteicoPetView.FRAMES`, доступные игре через `gameFrameResource(...)`.
- Добавлены два новых ресурса `ic_game_book_open.xml` и `ic_game_book_upright.xml` для всех препятствий обеих игр.
- Удалён устаревший `ChteicoRunnerActivity.java` и его entry из `AndroidManifest.xml`.
- Остальные PNG приложения, например обложки произведений, не удаляются.

**Файлы:** `ChteicoMiniGameView.java` (новый), `ChteicoActivity.java`, `ChteicoPetView.java`, `ChteicoStore.java`, `ActivityInfo.java`, `AndroidManifest.xml`, `res/drawable/ic_game_book_open.xml`, `res/drawable/ic_game_book_upright.xml`.

### Ограничения

Среда не содержит готового Android SDK и Gradle, поэтому `:app:assembleRelease` **не выполнялся**. Не подтверждены запуск и частота кадров двух игр на телефоне, реакция на паузу и сворачивание, позиция WordBoundary при реальном Edge TTS, а также точность восстановления в некоторых нестандартных документах.

После подключения к CI рекомендуется выполнить:

```bash
gradle --no-daemon :app:assembleRelease --stacktrace
```

Дополнительный QA на телефоне: все стадии эволюции, «Бегун» и «Летун» (запуск/выход/столкновения/перезапуск/пауза), сохранение рекордов; переключения Reader NORMAL→RSVP→CURSOR→TTS и обратно, фоновые переходы, возврат на сохранённую главу и реальный процент на карточке «Продолжить».
