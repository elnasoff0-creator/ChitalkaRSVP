# ПРОЧиталка v1.11.175-beta CLEAN — полная расшифровка

**База:** v1.11.174-beta CLEAN. **versionCode:** 17500. **versionName:** `1.11.175-beta`. **Состав:** полные исходники Android Java, ресурсы, Gradle-проект, тесты QA.

В этой версии реализован комплекс изменений по накопительному ТЗ v1.11.175 (P0/P1/P2). Главный принцип: избегать повторной работы, перепроверок и создания View/Bitmap, а не просто выполнять всю ту же работу в фоне.

## 1. Манга и комиксы — «Лента» и устранение прыжка к последней странице (P0)

**Файл:** `ComicReaderActivity.java`.

- Определение страницы по `offsetTop <= scrollY` при ненагруженных изображениях заменено выбором страницы по фактическим `getBoundingClientRect()` и пересечению с рабочей областью экрана. Страницы с нулевой/недействительной геометрией не определяются как текущие.
- Лента резервирует высоту элементов до начала загрузки через CSS `aspect-ratio: 3 / 4`; там, где HTML книги содержит реальную ширину и высоту, используются исходные атрибуты `width`/`height`.
- Сохранение позиции переведено на идентификатор страницы и относительное смещение внутри страницы. Старые абсолютные закладки открываются по совместимому сценарию. Для новых сохранений введён маркер `comic_anchor_v175:<bookUri>`.
- Восстановление позиции не запрашивает все изображения от 1-й до выбранной страницы. Приоритет отдан текущей, предыдущей и двум следующим картинкам. Убрано многократное ожидание загрузки всех предшествующих изображений.
- Удалено полное скрытие WebView (`setAlpha(0f)`) при смене главы, сохраняется фоновый цвет темы.
- Асинхронно подготовленные страницы связаны с **поколением главы**. URL изображения содержит токен `chapter/<generation>/page/<id>`, чтобы устаревший запрос не возвращал файл из новой главы.
- Подготовка ресурсов теперь выполняется из локального неизменяемого набора `PageAsset`; SAF URI изображения кэшируется внутри ресурса, сокращая повторные поиски `findFile()`.
- Сохраняются жесты, режим «Страницы», масштабирование, старые закладки и работа CBZ/CBR/HTML.

**Важная оговорка:** если изображения не содержат реальных размеров, базовая пропорция 3:4 — лишь резервирование места. Точную устойчивость позиции при больших расхождениях пропорций и медленном WebView требуется проверить на устройстве. Переход на нативный RecyclerView не выполнялся: сначала применён менее рискованный фикс существующей ленты.

## 2. Аудиоплеер аудиокниг — уменьшение микроподёргиваний (P0)

**Файлы:** `AudioPlayerActivity.java`, `SleepTimerBadge.java`.

- `SleepTimerBadge` меняет `LayoutParams` и видимость только если они реально изменились, а не при каждом секундном обновлении.
- Время книги, текущая позиция, проценты и иные статусы записываются в TextView только при изменении значений.
- `playIcon` обновляется только при переключении play/pause; кэш состояния сбрасывается при реальном пересоздании экрана.
- TTS `SpannableString` и подсветка речи обновляются только при изменении слова/диапазона или текста. Не выполняется повторное назначение равного содержимого на каждом тике.
- Название главы ограничено двумя строками, зарезервировано место текста; обложка остаётся на экране до загрузки новой и не должна мигать при смене источника.
- Оставлен действующий асинхронный `MediaPlayer.prepareAsync`, таймер сна и темы. Перестройка интерфейса при смене самой темы ещё допускается, если действительно меняется структура экрана; постоянное пересоздание при обычном тике исключено.

## 3. Обычное чтение и поиск по книге (P0)

**Файлы:** `MainActivity.java`, `ReaderActivity.java`.

- Устранена повторная полная сериализация каталога из 80-мс цикла по условию `index % 8 == 0`. Прогресс записывается по действительно новому индексу с ограничением частоты; при паузе остаётся принудительное сохранение.
- Сохранение при движении скролла также ограничено изменениями и временем, а не каждым показом той же позиции.
- Поиск внутри большой книги вынесен из TextWatcher в одиночный фоновый исполнитель. Добавлены debounce 250 мс и номер запроса: поздние ответы старого запроса не затирают новый.
- Вывод найденных мест через RecyclerView (первые 100 результатов); закрытие диалога останавливает ожидающие задачи и фонового исполнителя.
- Перемещение к найденному фрагменту и выделение текущего места сохраняются.

## 4. Edge TTS — не разбирать всю книгу заново для каждой главы (P0)

**Файлы:** `EdgeFullBookService.java`, `EdgeChapterArchive.java`, `EdgeOfflineIndex.java`, `EdgeChapterDownloadsActivity.java`.

- Добавлен краткоживущий `PreparedJob` для текста книги, подготовленных сегментов, их ключей и позиций слов. В пределах той же ревизии текста, голоса, скорости и словаря повторное задание главы использует готовые данные, не начинает полный разбор заново.
- Для ревизии документа используются URI и метаданные ContentResolver; кэш ограничен одной подготовкой и сроком 120 секунд, чтобы не накапливать большие книги в памяти.
- Поиск каталога сохранённых глав Edge TTS кэшируется по ключу дерева SAF и идентификатору книги, сбрасывается при инвалидизации архива.
- Длительная операция `snapshot()` теперь не удерживает общий монитор архива; чтение SAF выполняется в отдельном локе на группу идентификаторов книги (32 stripes), а короткие записи в кэш выполняются под локом. Эпоха кэша не позволяет результату устаревшего чтения перезаписать недавно инвалидированный индекс. `exportableCount()` больше не держит общий монитор во время `snapshot()`.
- Для расчёта готовности сотен глав создан `EdgeOfflineIndex.CoverageIndex`: одна подготовка отсортированного префикса, затем бинарный поиск диапазона, а не полный перебор всех MP3 для каждой главы. Алгоритм учитывает перекрывающиеся сегменты и проверен сравнением с исходным расчётом.
- Экран загрузки глав теперь использует **RecyclerView со стабильными ID**, а не сотни одновременно созданных карточек в ScrollView; обновления отдельных строк по событиям с сохранением состояния действий. Сохранены команды «Сохранить», «Перезагрузить» и «Удалить» для соответствующей главы.
- Ранее внедрённые раздельные MP3-фрагменты и WordBoundary, ленивое восстановление, финализация SAF и экспорт отдельных глав в аудиотеку без изменения формата.

**Граница изменений:** запись и удаление в `EdgeChapterArchive` всё ещё сериализованы глобально для безопасности индексов. Полный перевод всех mutating-операций на независимые очереди книг не выполнялся без проверок конкурентной записи на Android SAF; чтение снимка уже вынесено из глобальной блокировки.

## 5. Прямые загрузки и общий менеджер (P1)

**Файлы:** `LinkDownloadDetailsActivity.java`, `DownloadActivity.java`, `DownloadArchiveStore.java`, `UnifiedDownloadManagerActivity.java`, `DownloadWorker.java`.

- Экран прямой загрузки больше не пересоздаёт всю иерархию View каждые 1100 мс. Он строит карточки при изменении состава задания и адресно обновляет их прогресс/ошибки через `DownloadChangeBus`. Устаревший секундный тик и дублирование lifecycle-методов удалены.
- Карточки общего экрана загрузок переиспользуют созданные элементы, когда неизменны название, автор, описание, формат и основные статические свойства. Меняются только прогресс, статус и видимость действий. Состояние раскрытого свайпа вправо сохраняется.
- Расчёт DiffUtil для большого списка перенесён в одиночный фоновый исполнитель с номером поколения. Устаревший результат сравнения не заменяет более свежий.
- `DownloadArchiveStore.hiddenIds` кэширует множество скрытых идентификаторов в памяти до реальной мутации архива, вместо повторного полного разбора JSON на каждое обновление.
- Состояние загрузки аудиокниг по-прежнему сохраняется при завершении/паузе/ошибке, но промежуточная запись полного списка заданий ограничена интервалом (минимум 3,5 с) вместо ~600 мс.
- Менеджер файлов использует `DiffUtil` для частичных изменений списка вместо безусловного `notifyDataSetChanged`.
- Файловые и архивные операции остаются без удаления завершённых пользовательских глав при смене папки.

**Граница изменений:** прямые загрузки по-прежнему создают все строки *при первом* открытии большого задания; полностью виртуализированный RecyclerView для этого одного экрана остаётся дополнительной задачей после Android UI-профилирования. Бесконечная ежесекундная полная перерисовка устранена.

## 6. Обложки и аудиотека (P2)

**Файлы:** `ComicCovers.java`, `AudioLibrary.java`.

- Кэш обложек комиксов теперь ограничен суммарным объёмом Bitmap в памяти (12 МБ), а не только числом объектов. Не выполняется `Bitmap.recycle()` для Bitmap, ещё используемого отображаемой карточкой.
- Ключ по книге/главе позволяет проверить память и недавно сохранённый файловый кэш ДО дорогостоящего обхода `ComicLibrary.chapters()`.
- Декодирование миниатюр выполняется с downsampling, ревизии недавних дисковых файлов сохраняются через срок актуальности.
- Естественная сортировка аудиотреков переиспользует один предварительно скомпилированный Pattern, не применяет regex для определения каждой числовой группы.
- `AudioLibrary.merge()` строит индекс по ID книги вместо повторного линейного поиска каждой найденной записи; пользовательские названия/обложки сохраняются.

## 7. Рыбалка (P2)

**Файл:** `ChteicoFishingView.java`.

- Убрана неограниченная анимационная петля в статических фазах READY и неподвижного RESULT; изменения отображаются по событиям.
- Активные фазы CASTING/FLYING/REELING/BITE/CATCHING продолжают использовать прежний цикл 16 мс, таймеры поклёвки и усталости сохраняются.
- Изменения не затрагивают шансы редкости, массу, скорость рыбы, экономику или бонусы удочек.

## 8. Совместимость и неизменяемые функции

Сохранены функциональные сценарии v1.11.174: быстрое открытие готовой озвучки и WordBoundary, SAF смена папки в фоне с сохранением прежнего пути, экспорт одной MP3-главы как отдельного файла в общую папку аудиокниги с одной cover, swipe-to-archive вправо, настройки тем, OCR, чтение манги, рыбалка, скачивание книг/аудиокниг. Изменения не создают новые постоянные фоновые сканирования или телеметрию.
