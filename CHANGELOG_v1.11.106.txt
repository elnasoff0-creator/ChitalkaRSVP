CHANGELOG — ПРОЧиталка v1.11.106-beta CLEAN
Основа: v1.11.105-beta. 27 октября 2026 года.

1. РАЗБИЕНИЕ ТЕКСТА (800/500)
   - SentenceChunks.LIMIT: 900 -> 800.
   - EdgeSpeechSegments.MAX: 900 -> 800.
   - EdgeSpeechSegments.FIRST_TARGET: 900 -> 800.
   - EdgeSpeechSegments.FIRST_TARGET_PRIORITY: 600 -> 500.
   - Сохранено группирование по предложениям/абзацам/границам глав.
   - При ручном переходе первый MP3 начинается с выбранного слова; весь
     остаток предыдущего 800-символьного блока сохраняет порядок слов.
   - Применяется и к очередной подготовке полных книг, если она запрошена
     пользователем. Новый размер образует новый хеш MP3; старые кэши не
     удаляются, но не обязаны совпадать с новым текстом сегментов.

2. WORD BOUNDARY / ПОДСВЕТКА
   - EdgeWordTimings.at(): сохранена прямая синхронизация по позиции Media3
     (исходные тики Edge 100 нс преобразуются в миллисекунды без постоянного
     временного сдвига).
   - Данные с нулевой длительностью получают ограниченный интервал 500 мс,
     плюс небольшой допуск 90 мс; подсветка не зависает на слове в тишине.
   - Ограничен допустимый интервал подсветки началом следующего слова.
   - Диагностика количества успешно сопоставленных WordBoundary.
   - Существующие MP3 и sidecar .words.json читаются без миграции формата.

3. ПОТОКОВОЕ MP3 / MEDIA3
   - EdgePlaybackService: setBufferDurationsMs(450, 15000, 160, 350)
     вместо (500, 15000, 250, 500). Стартовое ожидание декодера снижено;
     повторная буферизация также запрашивает меньший порог.
   - EdgeLiveBuffer / EdgeLiveDataSource сохранили немедленную передачу
     байтов; аудио не ожидает полного MP3 для начала воспроизведения.
   - Возможное ухудшение при слабой сети требует проверки на телефоне,
     автоматическое увеличение частоты запросов не добавлялось.

4. ДИАГНОСТИКА ПРОИЗВОДИТЕЛЬНОСТИ
   - Новый EdgeTtsDiagnostics.java с трассировкой одного текущего MP3
     по обезличенному ключу: queued, socket-open, first-mp3,
     decoder-first-read, player-start, network-end, track-ended.
   - Для сетевых запросов автоматически записывается длительность этапов
     request->open, open->MP3, MP3->first read, first read->Media3 start.
   - Отдельно измеряется serial-gap между завершением предыдущего трека
     и фактическим запуском следующего (если меньше 30 секунд).
   - EdgeTtsClient.Callback: необязательный connected() при onOpen WebSocket.
     Другие реализации Callback не изменяют работу.
   - Ограничен размер реестра диагностических трасс, освобождение при
     отмене и ошибке. Логи не содержат текста книги, SSML или токена.
   - player-start не является подтверждённым моментом вывода на аудио ЦАП;
     лог отражает событие Media3 isPlaying.

5. СОХРАНЁННЫЕ ПРАВИЛА EDGE TTS
   - Без предварительного синтеза СЛЕДУЮЩЕГО блока.
   - Предыдущий WebSocket должен завершиться до выдачи слота следующему.
   - Вход в TTS может прогреть только текущий выбранный блок до Play.
   - Не изменены 403 Date recovery, 429 Retry-After, полный MP3-кэш,
     WordBoundary-сайдкары, MediaSession, UI и мини-питомец.
   - Формат аудио: audio-24khz-48kbitrate-mono-mp3 (без изменений).

6. ТЕСТИРОВАНИЕ
   - 18 shell QA-наборов проходят; включён новый
     qa/test_edge_timing_and_diagnostics.sh.
   - Тесты ограничения 800/500, полного покрытия слов без потерь,
     корректного продолжения аудио и непараллельных WebSocket.
   - Успешны заглушенные сценарии HTTP 403/429, отмены, потокового MP3,
     WordBoundary (в том числе нулевая длительность) и диагностики.
   - 100 Java-файлов прошли синтаксический разбор, 90 XML прошли парсинг,
     обе Python QA-проверки UI прошли.

ОГРАНИЧЕНИЯ
   - Android SDK отсутствует: Gradle assembleRelease/APK не выполнен.
   - Новые пороги Media3 и время между блоками не измерены на смартфоне.
   - Сервер Microsoft может ограничивать одиночные подключения (HTTP 429).
   - Короткие паузы между последовательными новыми блоками возможны.
