### Найдено и исправлено в ходе QA

В новой реализации `LinkDownloadDetailsActivity` в первый раз остались два lifecycle callback `onResume/onPause` (устаревший polling и новый event-based), что помешало бы Java-компиляции. Устаревшие методы удалены; контракт проверяет отсутствие повторных override. Также найден риск блокировки архива: `exportableCount()` с глобальным `synchronized` мог бы ожидать snapshot лок, который затем ждёт глобальную блокировку. Глобальная блокировка удалена из `exportableCount`, тест сохраняет это требование. В рыбалке сохранён активный цикл во всех фазах поклёвки/вываживания.

## Что НЕ подтверждено

- Команда Gradle `:app:assembleRelease` не запускалась — отсутствуют Android SDK и Gradle. Следовательно, полная семантическая компиляция **всего Android проекта** не подтверждена.
- Эмулятор, тесты на устройстве, реальная запись/чтение SAF, OEM Android FileProvider, поведение RecyclerView после жестов не запускались.
- Устранение мерцания WebView и микросдвигов плеера обосновано изменениями в коде, но **не измерено на устройстве**; результаты Perfetto/StrictMode отсутствуют.
- Из соображений безопасности глобально синхронизированные операции записи и удаления `EdgeChapterArchive` пока оставлены последовательными. SAF snapshot уже вне глобального монитора. Полный per-book write dispatcher потребует отдельных гонкоустойчивых Android-тестов.
- `LinkDownloadDetailsActivity` больше не перестраивает строки по таймеру, но при **первой загрузке** задания с сотнями файлов всё ещё создаёт список сразу, не RecyclerView. При необходимости дополнительно виртуализировать после замеров.
- Исторические тесты прежних версий, которые жёстко требуют старые versionCode, исключены из основного прогона. Актуальные функциональные сценарии покрыты v175 suite и Java-тестами.

## Критерии приёмки на Android

1. Включить debug StrictMode для выявления дискового I/O на UI; записать Perfetto на больших книгах/главе манги и при смене пути SAF.
2. На медленном SAF проверить сохранение исходного MP3/индекса при прерывании; отсутствие ложных 100% и WordBoundary пропусков.
3. Быстро менять главы манги в «Ленте», менять ориентацию и проверять якорь/отсутствие последней страницы и флешей.
4. Проверить все кнопки каждой виртуализированной строки менеджера Edge TTS, сохранение позиции списка, свайп вправо в общем менеджере.
5. Прогнать Gradle assembleRelease в GitHub Actions и при ошибке сохранить полный блок `> Task :app:compileReleaseJavaWithJavac FAILED` с первой строкой `error:`.
