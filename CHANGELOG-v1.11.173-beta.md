# CHANGELOG — ПРОЧиталка v1.11.173-beta CLEAN

**База:** v1.11.172-beta CLEAN Gradle Compile Hotfix.  
**Version:** `1.11.173-beta` / `versionCode: 17300`.  
**Назначение:** перестать объединять MP3 в обычном Edge TTS, оставить потоковое объединение только в явном экспорте отдельных глав в аудиотеку, переместить диагностику и добавить визуальные индикаторы полностью сохранённых загрузок.

## 1. Edge TTS: скачивание и офлайн-озвучивание без склейки MP3

### Было

Старые пути сохранения иногда формировали единый MP3 главы и могли выдавать ошибку объединения при завершении на 99%. Пункт «Автопреобразование озвучки главы в единый файл MP3» и ручные команды объединения сохраняли возможность вновь запустить этот процесс.

### Стало

- `EdgeFullBookService.java`: публикация выбранной главы всегда идёт через `EdgeChapterArchive.publishFragmentsOne(...)`; не вызывается объединение в один MP3 на этапе скачивания.
- `EdgeStreamingService.java`: аналогично, сохранение фрагментной главы в обычном потоке воспроизведения/озвучивания использует `publishFragments(...)`.
- `EdgeChapterActions.java`: повторное сохранение локального кэша использует `publishFragmentsOne(...)`; прежняя ручная команда слияния удалена.
- `EdgeChapterDownloadsActivity.java` и `UnifiedDownloadManagerActivity.java`: убраны элементы меню/действия, запускающие ручную склейку MP3 главы.
- `EdgeChapterArchive.autoMerge(Context)` всегда возвращает `false`. Старое значение `edge_auto_merge_chapter_mp3_v151` игнорируется; пользовательская настройка и связанный диалог удалены из `SettingsActivity.java`.
- Глава считается готовой после фиксации SAF-индекса **всех** требуемых фрагментов. Отдельные аудиочасти и WordBoundary остаются доступны для синхронизированного чтения. Уже существующие индексы режима `merged` остаются совместимыми с чтением и экспортом.

**Результат:** обычное завершение загрузки не зависит от сборки единого MP3. Не добавлен фоновый цикл проверки, не предусмотрено повторное чтение всего итогового MP3 после публикации. Сохранены оптимизации адресной публикации из v172.

## 2. Экспорт Edge TTS в аудиотеку: один MP3 на каждую готовую главу

### Новая команда

`DownloadActivity.java`, меню `⋮` карточки Edge TTS: **«Перенести готовые аудиоглавы едиными файлами в аудиотеку»** (вместо прежнего переноса фрагментами).

Команда выполняется исключительно по нажатию пользователя и после выбора дерева SAF. До выбора папки отображается подтверждение с числом полностью сохранённых глав. Разрешён частичный экспорт, например 3 готовые главы из 12: экспортируем только эти три, с оригинальными порядковыми номерами.

### Структура результата

```text
Аудиотека/
  Название произведения/
    cover.jpg                 # один общий файл, если локальная обложка есть
    001 - Глава 1. Начало.mp3
    002 - Глава 2. Дорога.mp3
    004 - Глава 4. Развязка.mp3
```

При отсутствии пригодного оглавления названия становятся `Глава 001.mp3`, `Глава 002.mp3` и т. д. Имена санитизируются для SAF; сортировка идёт по номеру главы.

### Реализация

- `EdgeChapterArchive.exportAudiobook(...)`: выбирает **только завершённые главы**, обходя подтверждённые SAF-манифесты. Повреждённый/нечитаемый индекс отдельной главы не останавливает перечисление остальных. Каждая глава получает отдельный MP3. Старые готовые объединённые главы могут экспортироваться как единственный входной источник.
- `EdgeMp3ChapterExport.java` — новый потоковый writer без полной загрузки главы в память. В явном экспорте читает MP3-кадры исходных фрагментов по порядку, отбрасывает локальные служебные ID3/Xing заголовки, объединяет **только фрагменты одной главы**, записывает ID3-текстовые метаданные `TIT2`, `TALB`, `TRCK` и не вставляет APIC.
- Для всех фрагментов одной главы требуется совместимый формат MPEG Layer III (версия, частота дискретизации, каналы); несовместимые/повреждённые источники приводят к понятной ошибке конкретной главы, без фиктивного успешного экспорта. Перекодирование/FFmpeg в APK **не добавляется**.
- В SAF создаётся/используется одна папка произведения. У обложки одно общее имя `cover.jpg`, `cover.png` или `cover.webp`, соответствующее локальному формату. Исходник обложки берётся **только из локального кэша**; сетевых обращений во время экспорта нет. Если обложки нет — не создаётся пустой файл. Старую общую обложку не дублируем.
- Исходные MP3-фрагменты, WordBoundary, оригинальные манифесты Edge TTS не перезаписываются и не удаляются.
- Уже подтверждённые MP3-главы повторно не создаются. Неподтверждённый файл, оставшийся после аварийного завершения, не перезаписывается молча: показывается сообщение для безопасного восстановления/смены папки.
- По завершении **каждой успешно закрытой главы** обновляется `AudioLibrary` с URI главы: сбой на следующей главе не стирает результаты предыдущих. Порядок глав сохраняется. Экспорт выполняется в отдельном потоке только после команды пользователя, без дополнительного фонового сканирования при обычных загрузках.
- `AudioLibrary.Book.coverUri` добавлено в сериализацию/загрузку JSON с обратно совместимым значением по умолчанию `""`. Обложка привязана к папке книги, а не к каждому MP3. `AudioLibrary.importTree(...)` распознаёт файл `cover.jpg`, `cover.jpeg`, `cover.png`, `cover.webp`.
- `MainActivity.java`, `AudioPlayerActivity.java` и `PlaybackArtwork.java` получают обложку аудиокниги по общему `Book.coverUri`, когда он задан. В `AudioLibrary.merge(...)` ранее выбранная общая обложка сохраняется, если новая книга пришла без неё.

**Важная граница:** это **не объединение книги целиком**. Формула экспорта — `N` полностью готовых глав → ровно `N` MP3 в одной папке, а не один MP3 на всю книгу.

- `SettingsActivity.java`: пункт `«Диагностика — Показать лог-файл»` удалён из раздела «Аудио» и добавлен **самым последним элементом вкладки «Общие»**.

## 4. Акцентный знак полной готовности ✅

- Новый `app/src/main/res/drawable/ic_download_chapter_complete.xml` — контурная галочка в круге, без градиента; акцентный оттенок выставляется программно через существующую палитру `UiColorScheme.accent(...)`, а не жёстко прописывается в ресурсах.
- `EdgeChapterDownloadsActivity.java`: мини-значок 16 dp при подтверждённом наличии сохранённых глав; обновление из состояния, полученного существующим способом, без отдельного таймера/полного рескана.
- `UnifiedDownloadManagerActivity.java`: мини-значок 16 dp у завершённой главы, при Edge TTS только в состоянии подтверждённого сохранения; временные 99% без фиксации не дают значок.
- `DownloadsRepository.java`/`DownloadActivity.java`: поле `confirmedReady`, значок 18 dp в карточке произведения Edge TTS **только если вся книга подтверждённо готова**; у прочих типов сохраняется определение готовности из их существующих статусов. Обновления используют действующие уведомления и кэши.

- `qa/check_v173.sh`: 16 тестов v173, независимая Java 17 семантическая компиляция архива с Android-заглушками, синтаксис 198 Java-файлов, XML-парсинг 174 файлов, 12 Java-проверок свайпа и 297 проверок баланса рыбалки.
