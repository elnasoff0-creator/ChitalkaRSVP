# ПРОЧиталка 1.11.183-beta CLEAN — полная расшифровка

**Основа:** `1.11.182-beta CLEAN`. **versionCode:** `18300`. Версия содержит изменения исходников по согласованному ТЗ; это не подтверждение успешного запуска APK на устройстве.

## 1. ReaderActivity — бейджи TTS без дополнительных подложек

**Изменён:** `app/src/main/java/ru/reader/rsvp/ReaderActivity.java`.

- Из `toolbarEngineBadge` удалена искусственная подложка `shape(buttonBg(),5)`.
- Удалён дополнительный `padding=1dp`; прозрачные пиксели PNG/WebP и собственный фон системной иконки сохраняются.
- Сохранились позиция 18×18dp в правом нижнем углу, контейнер 44×44dp, основная XML-иконка, обработчик нажатия и обновление фактически активного движка.
- Для Edge продолжает применяться встроенный `ic_edge_official.webp` (без установки браузера); для Android TTS — значок выбранного пакета.

## 2. ReaderActivity — удалить устаревший пункт меню

**Изменены:** `ReaderSheets.java`, `ReaderActivity.java`.

- Из обоих вариантов меню `⋮` удалён пункт **«Путь к файлам Edge TTS»**, включая графический ресурс в массиве строк меню.
- Явно переразмечены индексы TTS: `0` заметки, `1` закладки, `2` голос, `3` загрузка озвучки, `4` словарь, `5` поиск.
- Для остальных режимов: `0` заметки, `1` закладки, `2` загрузка озвучки, `3` словарь, `4` поиск.
- **«Загрузка озвучки» оставлена** и открывает именно единый менеджер загрузок текущей книги.
- Системный выбор SAF и внутренние обработчики разрешений **не удалялись**; папки управляются через «Настройки → Общие → Папки загрузок».

## 3. Edge TTS — устранение остановок между текстовыми блоками

**Изменены:** `EdgeStreamingService.java`, `EdgePlaybackService.java`, `EdgeLiveBuffer.java`.

### 3.1. Подготовка очередного блока заранее

- `pump()` теперь может присоединить к плейлисту готовый MP3 следующего блока **даже когда текущий MP3 ещё воспроизводится через WebSocket** и не записан на диск.
- Если следующий блок заранее синтезируется, его live-буфер подключается к Media3 после появления первых байтов; дожидаться `turn.end` для присоединения не требуется.
- Новый источник не вставляется в обход ещё не подготовленного текущего блока; сохраняется проверка `player.hasTrack(currentKey)` и порядок по начальному индексу слова.
- Если Media3 успел перейти в `STATE_ENDED`, но новый файл добавлен, `resumeEndedAt()` пытается продолжить с **ожидаемого** блока, не проигрывая снова завершившийся.

### 3.2. Обработчик завершения + страховочная проверка

- Создан общий метод `advanceAfterTrack(start,end,key,source)` для событий `onTrackFinished()` и восстановительной проверки.
- Применяются проверки текущей книги, активного Play, позиций, устаревших колбэков и дублирующих уведомлений. Завершение не может дважды сдвинуть `anchorWord` на следующий блок.
- `recoverEndedTransition()` вызывается существующим периодическим тикером (2,5 с), если плеер в `STATE_ENDED`, а пользователь не нажимал паузу. Дополнительный высокочастотный цикл не создаётся.
- На последнем слове книги и при таймере остановки сохраняется штатное завершение без циклического повторения.

### 3.3. Восстановление после неудачного источника Media3

- Ошибка декодирования и ошибка live-источника больше не трактуются автоматически как ручное нажатие Pause.
- `onTrackPlaybackError()` передаёт сервису номер блока, ключ, причину и тип источника.
- Live-задача при аварии полностью снимается из `liveJobs` и общей сети, после чего допускается одна ограниченная повторная попытка; отмена старого WebSocket не оставляет «вечную» запись о загрузке.
- Поздние сетевые callbacks отменённого задания не могут менять состояние нового фрагмента.
- Повреждённый кеш-файл выводится из плейлиста, удаляется в фоне вместе с некорректной разметкой, после чего синтезируется повторно.
- При повторном отказе устанавливается состояние ошибки; разрешённый пользователем резервный TTS может быть запущен через существующую проверку переключателя. При выключенном резерве он **не** запускается.

### 3.4. Ограничение ожиданий

- Для `EdgeLiveBuffer.read()` введён контроль отсутствия новых MP3-байтов: при **45 секундах** без данных возвращается `IOException`, вместо неограниченного `wait()`.
- Не отменяет стандартные более короткие таймеры WebSocket; не вмешивается в нормальное чтение готового MP3.
- Восстановление текущего фрагмента из SAF получает ограничение ожидания **9 секунд**. Если файловый провайдер завис, следующий проход `pump()` может выбрать сетевой путь, не блокируя интерфейс. Ранее начатая фоновая операция SAF может закончиться позднее; проверяются актуальные URI и ключ фрагмента перед применением её результата.

### 3.5. Диагностический журнал разработчика

Добавлены или расширены события `CLIP_FINISHED`, `NEXT_CLIP_SELECTED`, `NEXT_CLIP_WAITING`, `NEXT_CLIP_READY`, `NEXT_CLIP_STARTED`, `TRANSITION_STALLED`, `TRANSITION_RECOVERED`, `decode_error` и `saf_restore_timeout`. Не пишутся исходный текст книги или пользовательские данные. Журнал остаётся доступным только в режиме разработчика.

## 4. Контейнеры и значки помощи в настройках

**Изменён:** `SettingsActivity.java`.

- Устранён вспомогательный `addHelpIcon()`, добавлявший значок `?` отдельной строкой под настройкой.
- `headerWithHelp(title,section)` строит единый горизонтальный контейнер с заголовком и кнопкой помощи справа. Касательная область значка — **48×48dp**; заголовок получает оставшуюся ширину и может переноситься без наложения.
- Применено для редактирования меню, Чтейцо, подсветки, заметок, задержки запуска, выбора слова, курсора, размера порции, точки и линий фокусировки, цвета выделения, обычных и акцентных кнопок.
- Существующие встроенные значки помощи в аудиокарточках остаются в своей строке. Настройки и переключатели не изменяют свои значения.
- Убраны отдельно стоявшие строки со значком; другие отступы и интерактивные элементы сохранены.

## 5. Совместимость

- Сохраняются целостные предложения из `v1.11.182`, адаптивные размеры и стабильная группировка MP3 для конкретной книги.
- Не изменён формат кеша, идентификаторы папок, SAF URI, ключи словаря или настроек.
- Play/Pause и внешнее кольцо ожидания сохраняют своё поведение: кольцо отображается только при реальном ожидании, а не если текущий MP3 уже готов.
- Нет отдельного нового экрана загрузок; менеджер загрузок остаётся единым.
