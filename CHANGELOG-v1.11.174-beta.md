# ПРОЧиталка v1.11.174-beta CLEAN — полная расшифровка изменений

**База:** v1.11.173-beta CLEAN Full Source. **Версия:** `versionName 1.11.174-beta`, `versionCode 17400`.
**Тип релиза:** оптимизация отклика интерфейса, диска и выбранных SAF-папок; не меняет формат пользовательских книг, WordBoundary, а также механику игры «Рыбалка».

## 1. Edge TTS — быстрое открытие уже подготовленной книги (P0)

**EdgeStreamingService.java**
- `openBook()` больше не выполняет `EdgeChapterArchive.restore()` всей книги до установки `bookReady`. Текст и индекс открываются в фоновом `io` как ранее; UI получает готовность после получения локального каталога клипов, без обхода всех MP3 в SAF.
- Добавлен адресный `lazyRestore(Clip)`: восстанавливаются только действительно необходимые текущие/предстоящие фрагменты. Приоритетный поток `EdgeClipRestore` не ждёт очереди публикации готовых аудиоглав, которая остаётся на отдельном потоке.
- Ключи уже проверенных клипов регистрируются на текущую книгу/речевую ревизию: не предпринимаются повторные восстановительные попытки на каждом UI-тике. Отсутствие главы в SAF кэшируется до следующего события инвалидирования, поэтому новая книга не вызывает полный поиск папки для каждого MP3-фрагмента. Неудача ленивого восстановления позволяет перейти к существующему сетевому синтезу (плеер не зависает бесконечно).
- Готовое аудио после восстановления передаётся существующему `EdgePlaybackService`, с прежними метками WordBoundary. Отдельные готовые MP3/слова не пересоздаются при каждом открытии.
- Убран тяжёлый `DocumentFile.exists/isDirectory/canWrite` с интерактивного пути `warmCurrent()` и `startLive()`: перед сетевым запуском выполняется лёгкая проверка сохранённого разрешения, а фактические ошибки SAF обрабатываются при операции записи.

**EdgeChapterArchive.java**
- Добавлены `lazyChapter()` и `restoreClip()`: индекс и карта файлов читаются только для одной запрошенной главы, кэшируются в ограниченном LRU на 12 глав. Последующие фрагменты той же главы не перечисляют папку заново.
- При наличии готовых локальных MP3 и WordBoundary они используются сразу. Если локальных файлов нет, исходное аудио копируется однократно и SHA-256 проверяется при **новом** восстановлении; нет повторного хеширования уже имеющегося неизменного аудио при каждом открытии.
- Поддерживается старый индекс объединённых глав v1: восстановление ограничено выбранной главой, а не всей книгой.
- `snapshot()` и `savedBooks()` сохраняются до явного `invalidate()` после публикации, удаления, миграции или смены папки. Периодическая переинвентаризация неизменённого SAF больше не запускается исключительно из-за 9- или 15-секундного TTL.

## 2. Выбор SAF-папок — без блокировки главного потока (P0)

**DownloadFolderPicker.java**
- `receive()` принимает результат выбора и запускает проверку записи в `ExecutorService` (`PROChitalka-SAF-Picker`), а не в `onActivityResult` UI.
- Проверка write/read/delete остаётся для подтверждения полномочий, но выполняется в фоне. Предыдущий выбранный URI не заменяется до успешной записи пробного файла и транзакции SharedPreferences.
- При выборе отображается «Проверка доступа к папке…», по завершении — результат с конкретной причиной ошибки. Разрешение на прежнюю папку не отзывается, файлы не переносятся и не удаляются.
- `summary()` использует уже выданные разрешения и documentId без сетевого или удалённого `DocumentFile` запроса.
- Добавлен легковесный `granted()` для интерактивных сценариев. Полная файловая `available()` остаётся в фоновых операциях и по необходимости.

**Настройки и экраны**
- `SettingsActivity`, `DownloadActivity`, `UnifiedDownloadManagerActivity`, `MainActivity`, `EdgeFolderPicker`, `EdgeChapterDownloadsActivity`, `EdgeFullBookActivity`, `ReaderActivity` переходят на callback: продолжение загрузки, импорта или воспроизведения происходит только **после успешного подтверждения новой папки**, без гонки со старым URI.

## 3. Манга и комиксы — UI без тяжёлого стартового SAF (P1)

**ComicReaderActivity.java**
- Убрана синхронная `ComicLibrary.chapters()` из `onCreate()`. Сначала создаются управляющие элементы и WebView, отображается «Подготовка оглавления и страниц…».
- Структура глав и подготовка источников запускаются в фоновом потоке `comic-chapter-discovery`, после получения результата отображается первая глава; подсчёт страниц запускается отдельно после этого.
- Сохранены режимы «Страницы»/«Лента», ориентация, позиция, поведение WebView и асинхронная загрузка содержимого главы.

**MangaLibChapterDownloadsActivity.java**
- Вместо `ScrollView` с полной перерисовкой всех Views каждые 2,5 секунды используется `RecyclerView`, `AsyncListDiffer` и `DiffUtil` с идентификаторами томов и глав.
- Состояния читаются на `ExecutorService`; обновления поступают от существующего `DownloadChangeBus`, объединяются не чаще примерно одного раза в 320 мс и не «голодают» при непрерывном потоке изменений.
- Сводки томов рассчитываются одним проходом, без повторного сканирования всех глав на каждый том. Карточки и скролл остаются стабильными; действия «Скачать все»/«Пауза» и повторная загрузка сохранены.

**MangaLibStorage.java / MangaLibDownloadWorker.java**
- Для незавершённой загрузки между checkpoint-сохранениями обновляется оперативное состояние; данные пользовательского прогресса доступны UI через event-bus.
- Промежуточный `SharedPreferences.commit` теперь выполняется примерно раз в 8 страниц, при 2,5-секундном интервале или в конце главы. Состояния pause/fail/complete/отмена продолжают фиксироваться немедленно через `put`.
- Список сохранённых заданий кэшируется в пределах процесса, чтобы не парсить JSON после каждого изображения и проверки паузы. Сохранённые изображения остаются на диске и позволяют восстановить работу после принудительной остановки.
- **Пауза 250 мс на запрос к MangaLib сохранена**: её нельзя удалять без оценки HTTP 429 и ограничений источника.

## 4. Текстовое чтение, поиск и аудиокниги (P2)

**MainActivity.java**
- При открытии книги старым путём индекс слов и структура заголовков создаются в фоне (`PreparedText`), а на UI передаются готовые массивы без `prepareWords()` и полного regex-обхода текста.
- `findChapterForIndex()` использует бинарный поиск по подготовленным позициям глав вместо сканирования всего текста от начала до текущего слова.
- Поиск книг/аудиокниг загружает один снимок библиотек в фоне. Ввод дебаунсится на 200 мс, отображается максимум 100 совпадений с предложением уточнить поиск; файлы и SAF не загружаются заново на каждый символ.

**AudioPlaybackService.java**
- Добавлен кэш `durationPrefix`: префиксные суммы длительностей обновляются только после фонового анализа или изменения длительности главы.
- `getTotalDuration()` и `getTotalPosition()` перестали перебирать все треки каждую секунду. `MediaPlayer.prepareAsync()` и фоновый скан длительности не менялись.

## 5. Что сохранено

- Edge TTS: раздельные MP3/WordBoundary, синхронная подсветка текста, офлайн-кэш, пауза/продолжение, экспорт в аудиотеку отдельных глав (одна глава — один MP3, папка книги с единой обложкой), без автоматического объединения во время загрузки.
- Свайп загрузки **вправо** с кнопками «В архив» и «Отмена».
- Галочки завершения глав и произведений с акцентными темами.
- Рыбалка: вероятности редкостей, усталость и круговой таймер, бонусы удочек, скорости зелёной зоны.
- Остальные режимы чтения и TTS, комиксы, аудиокниги, заметки, OCR и библиотека не удалялись.

## 6. Ограничения релиз-кандидата

Прошли автономные QA-проверки, синтаксические/частичные Java typecheck, проверка XML и тесты чистых JVM-классов. **Полная `:app:assembleRelease` не запускалась:** нет локально установленного Android SDK/Gradle. Отзывчивость интерфейса, воспроизведение на медленных SAF-провайдерах и реальные гонки при смене папок необходимо проверить на устройстве. Ускорение пока не измерено в миллисекундах; проценты улучшения не заявляются.
