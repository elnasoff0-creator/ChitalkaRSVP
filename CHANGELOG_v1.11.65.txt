PROChitalka / Chteico v1.11.65-beta CLEAN
=======================================

Edge TTS: WordBoundary synchronization (adapted from the design of
https://github.com/sguzman/edge-tts ; not a copy of the browser extension).

Changed:
- EdgeTtsClient now requests speech.config with wordBoundaryEnabled=true.
- Parses Path:audio.metadata messages alongside MP3 audio packets.
- Reads 100-nanosecond WordBoundary offset/duration ticks and spoken text.
- Uses default +0% synthesis rate: WPM remains controlled by ExoPlayer playback speed.
- Added EdgeWordTimings.java: whitespace-token offsets, punctuation-normalized sequential
  matching, binary-search lookup by media position, and permanent JSON timing sidecars.
- New MP3 files and full-book downloads save *.mp3.words.json with a text hash and
  source-audio timestamps in the same persistent book directory.
- EdgeOnlineActivity no longer guesses highlighted word via elapsed-percent * word-count.
  It follows ExoPlayer.getCurrentPosition() with a lightweight 85ms UI highlight tick.
  If no accurate word metadata exists, the app does NOT fabricate word timestamps.
- Existing MP3 files remain intact. They can be listened to without changes;
  older MP3 without timing data will not have word-by-word highlighting until re-downloaded.
- Source clip resolution prefers the exact currently-playing MP3 key to avoid
  incorrect highlighting when multiple cached variants exist.
- Removing or re-downloading a clip removes its old timing sidecar too.
- The previous Android / Edge voice selections, book storage, downloads, WPM UI,
  queue, prefetch and all pet sprites are otherwise preserved.

Why the queue was not removed:
The root cause of incorrect highlighting was the fabricated time fraction, not the
bounded ordered download scheduler. The reference repo likewise uses grouped chunks.
Removing the scheduler now would risk stalling transitions, offline file reuse and
full-book downloads, without solving the synchronization bug.

Verification:
- Local isolated javac unit test of EdgeWordTimings alignment and time lookup passed.
- Existing Android project resources are validated as well-formed XML.
- New source ZIP verified for archive integrity.
- Android APK build and real Edge Read Aloud network/device tests NOT executed here:
  Gradle/Android SDK and live device/Edge service access are unavailable.

Caveats:
- Edge Read Aloud's consumer websocket is unofficial and may change.
- Metadata may omit tokens; unmatched spans are deliberately not highlighted.
- No guessed per-word highlight is displayed for pre-existing MP3 files without
  timing metadata. Use online queue -> redownload to obtain precise timestamps.
- Platform-level Media3 MP3 decoding latency may introduce small (< frame duration)
  device-specific differences; test on a physical Android phone.
