ПРОЧиталка v1.11.111-beta CLEAN — Edge TTS Quickify-inspired architecture
Дата: 28.10.2026
Основа: v1.11.110-beta CLEAN

СОДЕРЖИМОЕ
Исходный Android-проект (Java), Gradle-настройки, QA и описание изменений.
Собранный и проверенный на устройстве APK НЕ включён.

ГЛАВНОЕ
1. EdgeWebSocketPool: ограниченный пул из 4 ресурсов WebSocket. После штатного
   Path:turn.end соединение остаётся открытым и возвращается в пул. Следующий
   синтез может использовать тот же WebSocket без нового handshake.
   Ошибочные/отменённые сокеты НЕ возвращаются в пул.
2. EdgeSpeechQueue: до 4 активных TTS-заданий, из них не больше 2 фоновых
   предзагрузок. PLAY имеет приоритет над PREFETCH и BULK; полная книга не
   генерируется при интерактивном прослушивании. Старый режим одного запроса
   за раз заменён на диспетчер параллельных ресурсов.
3. EdgePrefetchPlanner: выбирает до 6 соседних кандидатов с ограничением по
   суммарным символам и количеству, затем сервис проверяет готовые MP3 и
   выполняемые задачи и только после этого отправляет сетевой запрос.
4. Сохранены live MP3 DataSource/Media3, WordBoundary, постоянный MP3-кэш,
   ключи по преобразованному тексту/голосу/скорости, паузы предложений.
5. 403: корректировка EdgeServerClock при валидном Date, одна повторная попытка.
   429: НЕ делать автоматические повторы; локальная пауза до 500 мс без роста.
   Сетевые сбои до первого MP3 кадра: не более 3 попыток с интервалами
   100 и 200 мс. При отмене локальное освобождение очереди <=500 мс;
   удалённое закрытие сервера за 500 мс не гарантируется.
6. Защита от поздних ответов по X-RequestId (если сервер присылает заголовок);
   однократный новый handshake при раннем закрытии переиспользованного WS.

ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА НА УСТРОЙСТВЕ
1. Обычный Play нового текста: первый MP3 и первое слышимое слово.
2. Последовательные запросы: количество новых handshake и повторный turn
   на сохранённом WebSocket; сравнить время с v1.11.110.
3. Сменить предложение в середине незавершённой предзагрузки, затем вернуться.
4. После смены Wi-Fi/мобильной сети: состояние пула и восстановление.
5. 403 (время), 429 (rate limit), закрытие сервером idle WebSocket.
6. MP3-кэш, WordBoundary и воспроизведение в фоне, включая MediaSession.

ГРАНИЦЫ ПРОВЕРКИ
JVM-тесты используют имитацию WebSocket и не доказывают, что текущий сервер
Microsoft принимает несколько SSML-turn на одном соединении. Протокол
Microsoft Edge Read Aloud не является публичным стабильным API. Рост
параллелизма до четырёх потенциально увеличивает HTTP 429. Эти риски
подробно указаны в QUICKIFY_PORT_V11111.md.
