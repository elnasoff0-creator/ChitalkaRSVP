# CHANGELOG · v1.11.185-beta CLEAN

## Причины регрессии v184

1. `GestureDetector.onSingleTapUp()` вызывал переход к слову до обработки
   `ACTION_UP` штатным контроллером выделения `TextView`. При долгом нажатии,
   слабом движении пальца и системных маркерах возникали гонки выделения и навигации.
2. `onBindViewHolder()` каждый раз устанавливал `setText()`, сбрасывая
   Android Selection и пересоздавая `Spannable` даже без изменения текста.
3. Межблочные маркеры выбирали ближайшие слова вместо точных символьных границ.
4. Каждое обновление подсветки TTS могло менять верстку и принудительно центрировать
   новое/предыдущее предложение, пока пользователь ещё выделял текст.
5. При отсутствии WordBoundary код возвращал позицию к началу уже играющего MP3.
   Тайм-аут старого `pendingTtsWord` мог допустить откат к предыдущей фразе.
6. Резервный Android TTS мог быть активен при чтении позиции из старого Edge.
7. Асинхронный callback завершения Media3 с тем же диапазоном слов, но другим
   ключом аудио, мог ошибочно завершить текущий фрагмент.

## Изменения

### ReaderActivity
- Удалён параллельный GestureDetector с немедленным `onSingleTapUp`;
  добавлен отложенный обработчик только подтверждённых коротких тапов.
- Система Android `setTextIsSelectable(true)` + `ActionMode` сохранена.
- Native ActionMode становится владельцем выделения на время работы; устаревшие
  `onDestroyActionMode` не очищают выделение нового текстового блока.
- При передаче действия в заметки/цитаты сохраняется точный диапазон до закрытия
  системного меню, включая асинхронное завершение меню.
- Неизменившийся блок не проходит повторный `setText`; сохраняются существующие
  `Spannable` и нативные handles.
- При активном системном выделении изменение динамических стилей блокируется,
  чтобы текст не менял разметку и положение маркеров.
- Сквозное выделение использует абсолютные символьные offsets для маркеров,
  точного текста, пунктуации и пробелов, без привязки движения к словам.
- Выделение имеет приоритет над автоматическим scroll-to-word; ручные переходы
  инвалидируют ранее отложенные задачи центрирования.
- Автоцентрирование TTS теперь происходит только когда предложение не видно,
  а не при каждом 180-мс обновлении слова.

### Edge TTS / навигация
- Новый `ReaderSpeechPositionGuard`: отсечение старых WordBoundary, MP3-пакетов,
  временно пустой разметки, отката подсветки во время ручного перехода.
- События старого трека, даже при совпадении `start/end`, не меняют состояние
  нового трека без совпадения полного ключа.
- В EdgeStreamingService введён номер явной навигации; нажатия Next/Previous
  гарнитуры/MediaSession отражаются в ReaderActivity согласованно.
- Резервный Android TTS использует собственное подтверждённое положение в книге;
  устаревшее положение Edge не используется для подсветки.
- При отсутствии таймингов текущий уже подтверждённый word index удерживается,
  вместо сброса на первый элемент MP3-блока.

### Совместимость
- Модель заметок/цитат и база SQLite не менялись.
- Словарь TTS, менеджер загрузок, кеш Edge, питомец и 50/50 реплики не изменены.
- Сохранённая позиция чтения не перезаписывается при обычном просмотре оглавления.
- Документы предыдущих версий удалены из архива.
