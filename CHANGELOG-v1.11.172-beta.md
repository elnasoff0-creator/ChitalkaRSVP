# ПРОЧиталка v1.11.172-beta CLEAN — полная расшифровка

**База:** v1.11.171-beta CLEAN  
**Версия:** `versionName 1.11.172-beta`, `versionCode 17200`  
**Тип пакета:** полный исходный проект, без APK.

## I. Edge TTS: завершение главы на 99% — переработка публикации

### Что наблюдалось до исправления

Загрузка доходила до 99%, а после завершения генерации программа могла показывать «Не удалось записать завершённую главу в выбранную папку Edge TTS». Исследование v1.11.154–157 против v1.11.171 выявило два проблемных механизма: сохранение с обязательным `.pending`/`renameTo()` и повторной проверкой SHA-256 через SAF после записи; и попытку опубликовать все готовые главы книги при завершении одной выбранной главы. Более поздняя версия также использует общую SAF-папку Book.

### Что сделано

1. **Адресная публикация:** добавлены `EdgeChapterArchive.publishOne()` / `publishFragmentsOne()` с отбором только нужной главы. `EdgeFullBookService.runJob()` вызывает их с `job.chapter`. Ошибка другой главы больше не делает завершение текущей главы ложным неуспехом.
2. **Одна запись MP3 в SAF:** новый документ создаётся под уникальным именем через `DocumentFile.createFile`; аудио записывается потоком (`FileInputStream` → `ContentResolver.openOutputStream(uri,"w")`) и закрывается. Для завершения не нужно переименовывать `.pending` в `.mp3`.
3. **Учитывается поведение SAF-провайдера:** в индекс главы сохраняются `audioFile`, `audioUri`, `wordsFile`, `wordsUri` непосредственно из созданных `DocumentFile`, а не предположения об их фактических именах. Чтение старых глав без URI работает через прежние имена.
4. **WordBoundary:** служебный `.words.json` сохраняется отдельно, также без rename; индекс считается подтверждением готовности только после успешного закрытия обоих файлов.
5. **Быстрая контрольная сумма:** SHA-256 собирается при уже выполняемом объединении MP3-кадров в локальный временный файл (`chapterDigest.update(fr.frames)`), поэтому повторное чтение полного MP3 через SAF **после записи удалено**. Восстановление из внешней папки и экспорт аудиокниги по-прежнему могут проверять целостность при чтении — эти операции имеют другую цель.
6. **Защита прежней главы:** новый MP3 и WordBoundary не перезаписывают прежние файлы. Сначала фиксируется `chapter.index.json`; лишь после успеха старые проиндексированные файлы можно удалить. При ошибке до фиксации новый неполный файл удаляется, прежняя версия остаётся в индексе. Если обновление индекса прервалось, код пытается восстановить прежний маленький JSON, не перечитывая MP3.
7. **Маркер книги:** `.edge-book.json` новой книги записывается напрямую; зависимость от переименования `.pending` удалена и с этого раннего этапа.
8. **Режим отдельных MP3-фрагментов:** адаптированы запись, реальные имена частей в индексе, восстановление, перечень готовых частей и экспорт. Старые имена вида `0001.mp3`/`0001.words.json` поддерживаются через значения по умолчанию. При ошибке новые файлы частей удаляются; предыдущие части удаляются лишь после сохранения индекса.
9. **Нет лишнего подтверждающего сканирования:** после успешной фиксации индекса `EdgeFullBookService`, экран ручного завершения и `EdgeChapterActions` доверяют результату публикации. Они не запускают немедленно новый `snapshot()` всей папки ради проверки уже закрытого MP3.
10. **Ленивое восстановление:** сохранённые главы не перечитываются целиком из SAF перед каждой загрузкой. `restoreChapter()` вызывается только если требуемые фрагменты выбранной главы отсутствуют во внутреннем кэше. Полное восстановление для иных старых сценариев сохранено.
11. **Реальная причина ошибки:** вместо общей фразы показывается строка с `publicationError()` и конкретным этапом: создание, потоковая запись, WordBoundary или индекс. При настоящей ошибке SAF 100% не выставляется.
12. **Повторная публикация без синтеза:** существующие действия «завершить сохранение» продолжают использовать уже подготовленные локальные MP3/WordBoundary; повторное обращение к Edge TTS не требуется, пока кэш цел. Если кэша нет, программа честно сообщает об отсутствии фрагментов.

### Что не менялось

- Алгоритм и голоса Edge TTS, скорость и настройки речи, WebSocket, приоритет живого воспроизведения, очередь синтеза и политика HTTP 429.
- Выбранная пользователем папка Book, права SAF, формат основного аудио и разметка WordBoundary.
- Ручная операция отдельного **экспорта полной аудиокниги** в AudioLibrary осталась независимой от описанного пути публикации главы и использует собственные проверки целостности.

## II. Онлайн-загрузки: частичный свайп ВПРАВО и работоспособные кнопки

### Причина старой проблемы

`DownloadActivity` использовал `ItemTouchHelper.SimpleCallback(...LEFT)` и `onSwiped`, хотя карточка не удалялась. Механизм swipe-to-dismiss удерживал состояние завершённого свайпа, пока экран пытался показать на той же строке обычные кликабельные кнопки. Параллельно `onChildDraw()` и `swipeFrame.post()` меняли смещение переднего слоя.

### Что сделано

1. Удалён `ItemTouchHelper` из логики архива. Добавлен `RecyclerView.OnItemTouchListener`, определяющий только горизонтальный жест.
2. Направление раскрытия изменено на **вправо**. Передняя карточка смещается вправо на реальную ширину действий, а под ней слева появляются «В архив» и «Отмена».
3. Смещение ограничено диапазоном `0 ... actionsWidth`. При отпускании карточка фиксируется раскрытой при достижении **42% ширины**, иначе возвращается. Жест влево по открытой карточке закрывает действия; обычный свайп влево по закрытой карточке не раскрывает архив.
4. После завершения свайпа больше нет `onSwiped()` и pending-cleanup; область кнопок освобождается для настоящего `OnClickListener`. Кнопки сохраняют прежние функции: архивирование `archive(item)` и отмена раскрытия.
5. Одновременно может быть открыта одна карточка; открытие следующей закрывает предыдущую.
6. Вертикальная прокрутка продолжает работать: захват происходит только после превышения системного порога движения и преобладания горизонтальной составляющей над вертикальной.
7. Один источник смещения — состояние `revealedSwipeId` при переразметке и непосредственное перемещение во время жеста; старый отложенный `swipeFrame.post()` удалён.
8. Продолжают работать темы, подтверждение при архивировании незавершённой загрузки, сохранение файлов, восстановление из архива, обычное меню карточки и фоновое обновление прогресса.
9. Вынесена чистая математическая логика распознавания жеста в `ArchiveSwipeMath.java`; её можно проверять без Android UI.

## III. Наследуемые возможности v1.11.171

Без изменения сохранены: временная усталость рыбы и пороги 90/80/70/65/60% (мерцающая −5 п.п.), замедление −30%, таймер восстановления 2/4/6/8/10 с для классов удочек, XML-иконка хвоста рыбы со стрелками вниз, запреты редкостей по удочкам, бонусы заполнения 0/+2,5/+5/+10/+15%, увеличение **падения** зелёной зоны после отпускания до 0,357/0,374 ед./с у удочки мастера/прочитателя, а также остальная рыбалка и другие функции ПРОЧиталки.

## IV. Список основных изменённых файлов

- `app/build.gradle` — 17200 / 1.11.172-beta.
- `EdgeChapterArchive.java` — адресная публикация, индекс с фактическими URI, однопроходный SAF, резервирование предыдущей главы, совместимость старых данных.
- `EdgeFullBookService.java` — публикация только активной главы, без повторного snapshot, ленивое восстановление.
- `EdgeChapterDownloadsActivity.java` — ручное завершение без дублирующего SAF-сканирования.
- `EdgeChapterActions.java` — ручная публикация без повторной проверки всей папки.
- `DownloadActivity.java` — правильный свайп вправо и открываемые кнопки.
- `ArchiveSwipeMath.java` — расчёт направления, смещения и порога раскрытия.
- `qa/` — проверки контракта и вычислений свайпа, актуализация устаревших проверок направления и версии.

## V. Проверка сборки

Автономные регрессионные проверки, Java-синтаксис и XML проверяются `sh qa/check_v172.sh`. **Полная сборка Gradle и проверка на телефоне не проводились:** в доступной среде нет Android SDK/Gradle. Пакет является полным исходным проектом, но не гарантированным APK. Сценарии проверки SAF и реальных касаний на устройстве приведены в QA-REPORT.
