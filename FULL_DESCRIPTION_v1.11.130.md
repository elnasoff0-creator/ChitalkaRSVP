# ПРОЧиталка v1.11.130-beta CLEAN — полная техническая расшифровка

**Основа:** v1.11.129-beta CLEAN Full Source.  
**Новый выпуск:** `versionName '1.11.130-beta'`, `versionCode 13000`.  
**Дата:** 04.11.2026.  
**Состав:** полный Android Java-проект со всеми предыдущими функциями и настоящими изменениями этого выпуска.

## 1. ReaderActivity — название и глава под рядом Toolbar

**Было:** текст «Название книги · Глава» занимал растягиваемую ячейку между кнопками самого Toolbar.  
**Стало:** ряд кнопок остаётся вверху; ниже него располагается отдельная скруглённая панель названия и текущей главы, в одну строку через разделитель `·`.

- `toolbarBookName` перенесён из `toolbar` в `toolbarStack`, на отдельную строку высотой 42 dp с отступом 6 dp.
- На прежнем месте создан `titleSpacer` с весом 1 для корректного выравнивания оставшихся кнопок.
- Не изменены обработчик открытия закладок при нажатии на название, стили тем и механизм обновления главы.
- При скрытии Toolbar скрывается весь `toolbarStack`, включая заголовок. Смещение анимации скорректировано для двух строк.
- Изменение охватывает общий `ReaderActivity`: обычное чтение, RSVP, курсор, системный TTS и Edge TTS. `ComicReaderActivity` не менялся.

**Файл:** `ReaderActivity.java`.

## 2. TTS — реальные границы предложений, история паузы, переход назад

**Проблема:** прежде `SentenceIndex.fromChunks()` трактовал каждый фрагмент синтеза до 800 символов как отдельное предложение. Длинное предложение разбивалось на «виртуальные предложения». Возврат с MediaSession мог рассчитываться от начала фрагмента, а не от фактически озвучиваемой части текста.

### Новая общая структура

- Переработан `SentenceIndex.java`: `fromText()` создаёт индекс целых предложений по исходному тексту с исходными границами символов и слов. Размер аудиоблока на это не влияет.
- Добавлен `TtsSentenceHistory.java`: хранит текущее и ранее наблюдавшееся предложение, запоминает остановленное предложение при Pause и вычисляет позицию *одного предыдущего реального предложения* при возобновлении, когда включено «Повторять предыдущее предложение».
- Подсветка всего предложения в `ReaderActivity` теперь использует тот же `SentenceIndex`, что и навигация. Для длинного предложения она не меняет границу из-за очередного MP3-фрагмента.
- В системном TTS `AudioPlaybackService` определяет актуальное слово по `LocalTtsWordTimings`, если такие данные доступны, с запасным вариантом — словом начала текущего блока. При паузе снимок сохраняется в сервисе, а не в Activity. Команды Next/Previous переходят к началу реального следующего/предыдущего предложения.
- В Edge TTS `EdgePlaybackService` уведомляет `EdgeStreamingService` о реальном Pause через `setPauseSelection(...)`. Последний получает позицию с учётом доступных `WordBoundary`, фиксирует предложение и при следующем Play выбирает начало предыдущего реального предложения. Медиауправление, гарнитура и экран приложения используют эту же цепочку.
- При ручном выборе предложения сбрасывается отложенный снимок паузы, чтобы поздний Play не возвращал к устаревшему месту.
- Сохраняются ограничения на последовательную работу Edge WebSocket, кеш и существующая логика независимых аудиосервисов.

**Что не меняли:** блоки синтеза `SentenceChunks` по-прежнему ограничены 800 символами; они остаются единицами генерации звука, но не навигации по тексту.

**Файлы:** `SentenceIndex.java`, новый `TtsSentenceHistory.java`, `ReaderActivity.java`, `AudioPlaybackService.java`, `EdgePlaybackService.java`, `EdgeStreamingService.java`.

**Уточнение поведения:** команда «Назад» начинает предыдущее предложение; после Pause → Play с включённой настройкой повторения озвучка также начинается с предыдущего предложения. С выключенной настройкой Play сохраняет прежний механизм продолжения. На самом первом предложении возврат остаётся в начале первого.

**Ограничение:** когда движок не выдаёт достоверные словесные временные метки, точная позиция *внутри* текущего предложения оценивается по известному аудиоблоку. Реальную синхронизацию на устройствах с разными Android TTS и Edge необходимо проверить отдельно.

## 3. MainActivity — поднятие Toolbar и одинаковый отступ сверху списка

- Удалён дополнительный `23 dp` верхний отступ из `drawHome()`. Системные отступы остаются в `SafeSystemBars`.
- Между закреплённым Toolbar и первой секцией ScrollView устанавливается `12 dp` только в обычном режиме.
- В режиме редактирования собственная панель команд продолжает управлять отступами; дублирование верхнего промежутка не добавляется.
- Сам Toolbar остаётся отдельным от ScrollView, поэтому первая карточка не должна визуально заходить на кнопки.
- Единая система расстояний между самими секциями, созданная в предыдущем выпуске, сохранена.

**Файл:** `MainActivity.java`.

## 4. Три самостоятельные карточки «Продолжить» в едином стиле

В Главном экране по-прежнему три независимых секции: «Продолжить чтение», «Продолжить аудиокнигу», «Продолжить комикс».

### Согласованные общие параметры

- Обложки всех трёх карточек: **88 × 88 dp**, скруглённые края и текущая тематическая палитра.
- Заголовок произведения: **17 sp**, максимум две строки.
- Информация о прогрессе: **12 sp**.
- Кнопка по образцу исходной компактной «Продолжить книгу»: текст 12 sp, внутренние отступы 8 × 6 dp, размер по тексту, без символов `▶` и без эмодзи.
- Положение текста относительно обложки: слева обложка, справа название, статистика и кнопка, внутренний отступ карточки 14 dp, промежуток 12 dp.
- Отдельные лейблы секций «Продолжить чтение/аудиокнигу/комикс» не добавляются (они были убраны ранее).

### Статистика

- **Текстовая книга:** `Глава … · Поз. 124/680 · 18%` (значения примерные). Вместо фрагмента текста — только текущая глава, позиция и процент. Если известно только число слова без общего количества, показывается `Поз. N`, без вымышленного знаменателя.
- **Аудиокнига:** `Глава 1/12 · 12:10 · 4%`, где временная позиция внутри текущей главы читается из сохранённого `audio_pos:<id>`.
- **Комикс:** сохранён согласованный формат `3/18 · Стр 12/47 · 13%`, вычисляемый по фактическому индексу страниц.

Сохранение `wordCount` добавлено в метаданные книги, которые записываются при чтении и озвучивании. Существующие записи без этого поля сохраняют совместимость и будут дополнены при следующем открытии.

**Файлы:** `MainActivity.java`, `ReaderActivity.java`, `AudioPlaybackService.java`.

## 5. Круглая кнопка раскрытия библиотек

- У заголовков **Библиотеки, Аудиотеки и Комиксотеки** оставлена прежняя функция раскрытия/сворачивания списка.
- Вместо текстовых стрелок `⌃` / `⌄` используется отдельная круглая кнопка с **заполненным треугольником**. В свёрнутом состоянии он направлен вниз; в развёрнутом поворачивается вверх.
- Нажатие по заголовку или по круглой кнопке выполняет то же действие. Сохранение раскрытого состояния по-прежнему работает.
- Создан ресурс `ic_library_triangle_down.xml`.

**Файлы:** `MainActivity.java`, `res/drawable/ic_library_triangle_down.xml`.

## 6. Три вертикальные точки у конкретных произведений

Внутри списков трёх библиотек **каждая строка книги, аудиокниги или комикса** использует справа минималистичную кнопку `⋮` без отдельной цветной круглой подложки.

По нажатию сохраняются прежние три действия:

1. «Открыть / Продолжить».
2. «Сделать текущей».
3. «Убрать из библиотеки» — после подтверждения, удаляется только запись приложения, не физические файлы.

Долгое нажатие по произведению не вызывает это меню. Короткий тап по строке открывает произведение.

**Файл:** `MainActivity.java`; используется существующий `ic_more_vertical.xml`.

## 8. Проверки и ограничения

Выполнены **12/12 групп локальных проверок**: 25 контрактов новой версии, Java-парсер для 132 исходных файлов, 111 XML-ресурсов, 107 разрешённых drawable-ссылок, исполняемые Java-тесты границ/истории предложений и регрессия прежних функций.

Один первоначальный прогон исторического теста Edge clock не прошёл из-за ограничения времени выполнения тестового callback; повтор и финальный прогон выполнились успешно. Важно повторить тест в CI при необходимости.

**Не выполнялись:** полноценная сборка `:app:assembleRelease` и запуск на физическом Android-устройстве (в данном окружении нет Android SDK и установленного Gradle). Синтаксический парсер не заменяет Java type checking с Android SDK, поэтому build success не заявляется.

После распаковки запустить:

```bash
gradle --no-daemon :app:assembleRelease --stacktrace
```

Дальнейшие обязательные испытания: высота Toolbar на устройствах с вырезами, перенос строки длинных названий, раскрытие библиотек, точность возврата системного/Edge TTS после паузы с гарнитурой и уведомлением, отсутствие сброса позиции при смене плеера.
