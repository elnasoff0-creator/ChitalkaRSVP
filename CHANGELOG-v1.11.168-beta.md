# ПРОЧиталка — v1.11.168-beta CLEAN

**Основа:** v1.11.167-beta CLEAN + ThemeFix.  
**Идентификатор сборки:** `versionCode 16800`, `versionName 1.11.168-beta`.  
**Формат передачи:** полный исходный проект Android Java. **APK не включён:** в среде подготовки отсутствуют Android SDK/Gradle; проверка на устройстве ещё необходима.

## 1. Экран «Загрузки» — отказ от периодического полного сканирования

- Удалён вызов `refresh()` по таймеру каждые 2600 мс и защита, запускавшая полный обход примерно раз в 7 секунд.
- `DownloadsRepository.load()` остаётся для первичной индексации при отсутствии сохранённого списка, явно запрошенной полной проверки и некоторых массовых операций.
- В обычном режиме карточки открываются из `DownloadListSnapshot`, а изменения поступают от источников загрузок через `DownloadChangeBus`.
- События с идентификатором задания объединяются в небольшие пачки; после этого через `DownloadsRepository.loadOne(id)` обновляются только изменившиеся карточки.
- Списки разделов и их счётчики пересчитываются из уже имеющихся карточек без обхода хранилищ.
- Сохранение снимка не блокирует главный поток; предел сохранённого списка увеличен со 150 до 1200 позиций.
- После возобновления Activity применяются события, поступившие, пока экран был скрыт. Для задач, остававшихся активными, выполняется адресная сверка.
- Готовые и остановленные задания больше не проверяются бесконечно по таймеру.

## 2. Меню «⋮» на карточках

- Удалена принудительная предварительная проверка `previewOnly` перед открытием меню.
- Стандартные меню открываются сразу по сохранённому состоянию карточки.
- Если выбранное действие требует проверенного задания (удаление, архивирование, переименование, перенос, управление конкретной очередью), выполняется адресная проверка `DownloadsRepository.loadOne(id)` уже после выбора пункта.
- Удалён глобальный поиск выбранной загрузки через `DownloadsRepository.load()` в `resolvePreview()` и в обработчике переноса.
- Проверка наличия готового HTML у Ranobes/RanobeLIB перенесена из построения меню на команду «Читать HTML» и выполняется в фоновом потоке.
- Сообщение «Проверяем выбранную загрузку…» больше не показывается при обычном открытии меню.

## 3. Универсальный «Менеджер» — событийная загрузка данных

- Удалён периодический `reload()` каждые 4200 мс.
- `reload()` получает конкретное произведение через `DownloadsRepository.loadOne(id)`, а не индексирует все типы загрузок.
- При изменении выбранного задания по `DownloadChangeBus` выполняется объединённое обновление с задержкой 350 мс, а не непрерывный опрос.
- Ревизии позволяют заметить изменения, пришедшие после скрытия экрана; UI-подписки корректно снимаются при `onPause()` и `onDestroy()`.
- Повторное поступление события во время фоновой загрузки не порождает очередь параллельных проверок: после текущей применяется одна отложенная.

## 4. Быстрое отображение глав и файлов

- Добавлен `DownloadRowsSnapshot`: отдельный кэш строк глав/файлов конкретного произведения в `filesDir/download_rows_v168`.
- При открытии сначала отображаются сохранённые строки; их актуальные данные и ссылки на задания проверяются в фоне.
- Кэш **только для отображения**: по строке без проверенного объекта нельзя выполнять операции с файлами. Для действий она сначала актуализируется.
- При обновлении адаптер использует уже существующее сравнение строк, вызывая `notifyItemChanged()` только для изменившихся позиций; сохраняются прокрутка и состояние вкладок.
- Для аудиокниг размеры завершённых, невыбранных и остановленных глав переиспользуются из кэша, чтобы не вызывать `DocumentFile` для сотен неизменившихся файлов при изменении одного активного трека.
- Существующий `edgeTocCache` сохранён: оглавление Edge TTS повторно не загружается при каждом обновлении прогресса.
- Снимок главы Edge TTS продолжает использовать собственный короткоживущий кэш `EdgeChapterArchive`; обновление публикации MP3 теперь отправляет событие выбранного произведения.

## 5. Точный прогресс и управление очередями

- Изменение одной загрузки обновляет её карточку и общий процент менеджера.
- Play/Pause остаётся отдельным действием от «Скачать всё» / «Подготовить всё».
- «Скачать всё» по-прежнему запускает постановку в очередь недостающих глав, не подменяется возобновлением текущей задачи.
- Не удалена логика действующих загрузчиков, повторов, удаления файлов, экспорта и восстановления.
- Сохранились ограничения на действия с завершёнными файлами и проверка разрешений SAF.

## 6. Единый стиль кнопок и цветовых тем

- Play/Pause, «Скачать всё» и кнопка выбора папки формируются через общий `actionIcon`: единые размеры, контур, отступы, акцент и состояния.
- Экран «Загрузки», «Архив» и «Менеджер» продолжают использовать наследуемое из ThemeFix оформление `UiColorScheme` и `ReaderButtonColors`.
- Индикаторы прогресса подстраиваются под акцентную палитру из настроек.
- Добавлен `PalettePopupMenu`: всплывающее меню принимает фон, текст, контур и акцент **из действующих пользовательских цветов при каждом открытии**. Замена применена к меню «Загрузок», «Архива» и «Менеджера» вместо статичного бежевого `chitalka_popup_surface`.
- Кнопка ручной проверки загрузок использует новую контурную векторную иконку `ic_refresh_download` и текущий цвет текста.
- Любые будущие элементы UI должны наследовать эту же палитру; не использовать зашитые белые/бежевые фоны и чёрный текст, не учитывающие тему.

## 7. Вкладка «Инфо» — расположение файлов

- Отображение папки изменено: **серая подпись «Файлы»** расположена над путём основного цвета текста.
- Путь может занимать **до двух строк**; ему выделена вся ширина, оставшаяся после иконки выбора папки.
- При нехватке ширины сокращаются начальные каталоги; окончание пути и последняя папка имеют приоритет.
- Необязательный текст «Внутренняя память» для основного тома удаляется; при этом фактические имена каталогов сохраняются.
- Для прямых ссылок путь выводится из SAF tree URI при возможности, с реальным подпапочным суффиксом задания.
- Если хранилище сохранило URI конкретной папки произведения (MangaLib, RanobeLIB, Ranobes либо перенесённые аудиофайлы), путь определяется по этому URI; иначе отображается достоверный путь настроенной общей папки категории.
- Не используются выдуманные файловые пути: непрозрачные SAF URI показывают только подтверждённую часть расположения.
- Для новой темы автоматически подстраиваются цвет метки, основной цвет пути и фон строки.
- Неизменившиеся сведения вкладки «Инфо» повторно не создаются при каждом событии прогресса.

## 8. Файловая безопасность и проверка вручную

- В панели «Загрузок» добавлено действие **«Проверить загрузки»** с подтверждением: полная сверка запускается только по запросу.
- Отдельные действия удаления/перемещения/архива проверяют актуальное задание и сохраняют существующие подтверждения.
- Изменение папки SAF и массовые операции могут инициировать отдельную полную сверку, поскольку затрагивают более одного задания.
- Готовые кэшированные строки не разрешают файловые операции до получения фактического объекта задания.
- Изменения от хранилищ поступают только после записи их состояния; при перезапуске приложения источником истины остаются реальные журналы заданий, а не UI-кэш.

## 9. Уведомления хранилищ

Уведомления о затронутом произведении добавлены для:

- `BookImportManager` (аудиокниги);
- `LinkDownloadStore` (скачивание по ссылке);
- `MangaLibStorage` (главы CBZ);
- `RanobeLibStorage` (HTML ранобэ);
- `RanobesStorage` (Ranobes);
- `EdgeFullBookStore` и `EdgeChapterArchive` (подготовка и публикация Edge MP3);
- `DownloadsRepository.hideEdge/showEdge` (отображение Edge);
- `DownloadArchiveStore` (архивирование, восстановление, удаление).

`DownloadChangeBus` хранит ограниченный журнал изменений с монотонной ревизией. Когда Activity возвращается, она получает пропущенные ID; при переполнении журнала выполняется согласование списка.

## 11. Совместимость и границы тестирования

Функции и механизмы предыдущего релиза не были специально удалены. Однако **Android APK не собран и на реальном устройстве не проверен**. Доступная проверка исходников включает синтаксический разбор Java, разбор XML, статические регрессионные проверки 168-й версии и отдельный тест уведомлений на JVM со стендовыми Android-классами. Для подтверждения исправления в устройстве необходимы Gradle-сборка, установка и проверка загрузчиков, SAF, меню и смены тем.

Особенно важно испытать: параллельные загрузки, большое число глав, процесс после принудительной остановки, отзыв SAF-доступа, миграцию со старых версий, перенос, архив, удаление, навигацию и восстановление прогресса.


## Hotfix компиляции v1.11.168-beta (GitHub Actions, 15.11.2026)

По полному логу `:app:compileReleaseJavaWithJavac` исправлены все шесть явно указанных ошибок компилятора:

- `UnifiedDownloadManagerActivity.java` (2 `illegal forward reference`): объявление `reloadDebounced` перенесено выше поля `downloadListener`, чтобы инициализатор слушателя обращался только к ранее объявленному полю.
- `EdgeChapterDownloadsActivity.java` (4 ошибки `non-static variable ... cannot be referenced from a static context`): `stateColor(Entry)` сделан экземплярным методом, поскольку цвета `UiColorScheme` и поля `ACCENT`/`MUTED` зависят от темы текущей Activity.

Логика загрузок, настройки темы, versionName/versionCode и другие функции не изменены. Добавлен статический регрессионный тест на эти два дефекта.

**Проверки:** тесты исходников выполнены локально. Повторную настоящую Android/Gradle сборку в текущей среде провести невозможно из-за отсутствия SDK и Gradle. Статус успешного `assembleRelease` должен быть подтверждён новым запуском GitHub Actions.
