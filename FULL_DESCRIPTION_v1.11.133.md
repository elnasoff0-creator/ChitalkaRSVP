## 2. Выбор предложения при возобновлении TTS после Pause → Play

Новый файл: `TtsResumeChoice.java`. Изменённые: `SettingsActivity.java`, `TtsSentenceHistory.java`, `AudioPlaybackService.java`, `EdgePlaybackService.java`, `EdgeStreamingService.java`.

В разделе **Настройки → Аудио → TTS** вместо старого переключателя появился выбор:

- **С начала предыдущего предложения**;
- **С начала текущего предложения**.

При установке обновления прежнее значение `tts_resume_previous_sentence` мигрирует логически, без потери настроек: старое `true` соответствует «предыдущему», старое `false` — «текущему». Новая настройка хранится в `tts_resume_sentence_mode`, а прежний ключ поддерживается для совместимости.

Определение текущего/предыдущего предложения привязано к **реальному предложению исходной книги**, а не к 800-символьным фрагментам синтезированного MP3. `TtsSentenceHistory` хранит снимок предложения в момент паузы.

**Edge TTS:** служба воспроизведения вызывает общий обработчик выбора при следующем явном Play, в том числе при управлении с гарнитуры и через MediaSession. `EdgeStreamingService` выбирает границу соответствующего полного предложения. Навигация «Назад»/«Вперёд» остаётся самостоятельной и не зависит от нового значения.

**Системный Android TTS:** при возврате к предложению служба определяет его позицию внутри текущего синтезированного аудиофрагмента. Если доступен файл с точными временными метками слов, MediaPlayer перематывается к началу выбранного предложения; если меток нет, оставшаяся часть фрагмента озвучивается напрямую от выбранной текстовой позиции. Поэтому выбор не должен возвращать читателя к началу произвольного аудиоблока. При невозможности получить метки подсветка слов внутри такой прямой озвучки может быть менее точной — требуется проверка на реальных голосовых движках.

Единый прогресс книги, отдельная навигация по предложениям и настройки WPM сохранены.

## 3. MangaLib: исправление «Недопустимые данные изображения»

Файлы: `MangaLibApi.java`, `MangaLibDownloadWorker.java`.

Ранее серверу посылался заголовок `Accept: image/avif,...`, но распознаватель принимал только JPEG/PNG/WebP/GIF; AVIF/HTML/JSON возвращали одну общую ошибку. Также для относительных адресов использовался только первый CDN из списка MangaLib.

Сделано:

1. Запрос изображений ограничен совместимыми **JPEG, PNG, WebP и GIF**. AVIF больше не предлагается в `Accept`.
2. В каждой странице сохраняется список до **четырёх** допустимых CDN-адресов из списка серверов MangaLib. При ошибке транспорта, некорректном MIME или недекодируемом изображении разрешён повтор с альтернативного CDN.
3. Доступ к доменам проверяется по существующему allowlist; произвольные URL и перенаправления на неизвестные хосты не принимаются.
4. **HTTP 401/403** останавливают загрузку главы без обхода через зеркала. **HTTP 429** также не приводит к смене CDN: его обрабатывает предусмотренный отложенный retry Worker, максимум в рамках ранее существовавшего лимита попыток.
5. Ответы CDN проверяются по реальной сигнатуре данных и через `BitmapFactory.Options.inJustDecodeBounds` (без загрузки полного изображения в память). HTML/JSON, AVIF и повреждённые данные различаются диагностически.
6. Данные читаются потоково, с ограничением **25 МБ на страницу**, включая случаи без заголовка `Content-Length`.
7. Сообщение об ошибке включает **номер главы/страницы, хост CDN, HTTP-код/Content-Type и тип данных**, когда они доступны. Не сохраняются исходные HTML/JSON вместо изображения.
8. После создания `.part`-архива CBZ дополнительно проверяются количество записей, наличие `ComicInfo.xml`, возможность прочитать каждую запись и контрольная сумма ZIP. Только потом `.part` переименовывается в финальный `.cbz`.
9. Если API возвращает абсолютный URL страницы, при доступности списка CDN подбираются альтернативные узлы с тем же путём, **без копирования потенциальных URL-токенов в другой домен**.

**Примечание:** приложенный пользователем `vol1.cbz` проверен отдельно: 205 страниц JPG, 0 повреждённых. Это подтверждает, что JPEG сам по себе не является причиной ошибки, но не устанавливает конкретный формат неуспешного ответа на Android. Новый загрузчик улучшает диагностику и обработку таких ответов; реальную работу с сетью MangaLib необходимо подтвердить на устройстве.

### Что рекомендуется проверить на устройстве

1. MangaLib → скачать несколько отдельных глав (обычная JPEG-манга), проверить открытие и количество страниц CBZ.
2. При ошибке CDN посмотреть текст диагностики с номером страницы и типом ответа. Проверить, что ограничение доступа HTTP 403 корректно отображается и не обходится.
3. Edge TTS и системный TTS: Pause в середине предложения → Play при каждом из двух вариантов настройки; повторить через уведомление/гарнитуру.
4. Системный TTS с локальным голосом, который поддерживает и не поддерживает `onRangeStart`, на предложениях внутри 800-символьного блока.
5. ReaderActivity в портретной/альбомной ориентации: заголовок не перекрывает кнопки и открывает закладки.
