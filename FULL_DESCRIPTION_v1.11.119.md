# ПРОЧиталка v1.11.119-beta CLEAN — исправления TTS, оглавления и таймеров

**Версия:** `1.11.119-beta`
**versionCode:** `11900`
**База:** v1.11.118-beta CLEAN PERFORMANCE FIX. Все ранее внедренные функции сохранены.

## Исправления

### 1. Немедленная синхронизация UI после Play

`ReaderActivity.queueTtsUi(delay)` отслеживает время ближайшего запланированного callback. Если при Pause ожидается обновление через 15 секунд, то событие Play, смена Edge-трека или локальное `ACTION_STATE` **переносит проверку на текущий цикл UI**, удаляя отложенный callback. Пока TTS воспроизводится, резервный опрос идет каждые 180 мс; при паузе опрос слова выключен.

### 2. WordBoundary при первом MP3 и после переходов

Загрузка файла меток Edge WordBoundary перенесена из главного потока в однопоточный executor. Сначала используются доступные метки живого потока; после появления sidecar `.words.json` он загружается асинхронно, даже если MP3 уже существует. Если корректные временные метки еще не получены, не выдумываются позиции слов: поддерживается начальная позиция аудиофрагмента и показывается целиком активное предложение в overlay. При поступлении меток — обычная точная подсветка/постепенный overlay.

`pendingTtsWord` по-прежнему защищает от устаревших событий, но освобождается при подтвержденном текущем клипе в нужном предложении или после 8 секунд ожидания, если звук действительно воспроизводит проверенный клип. Добавлено журналирование `WORD_TIMINGS_EMPTY` и `PENDING_SELECTION_RELEASED`.

### 3. Оглавление с первого выбора

`previewTocDuringPlayback()` перемещает `RecyclerView` к блоку выбранной главы, затем выравнивает строку начала главы относительно панели управления на кадре после layout; при отсутствии `ViewHolder` повторяет попытку, максимум 12 кадров. Позиция TTS, очередь и озвучивание не меняются. Просмотр главы теперь работает также когда Play уже запрошен, но звук еще буферизуется. Ручная прокрутка отменяет отложенное выравнивание. Возврат к произносимому тексту — только по явному действию пользователя.

### 4. Независимые таймеры сна по фактическому времени звучания

Новый класс `PlaybackSleepCountdown` использует два НЕЗАВИСИМЫХ persistent key:
- `tts_sleep_remaining_ms` — общий для Android TTS и MS Edge TTS.
- `audiobook_sleep_remaining_ms` — только аудиокнига.

Обратный отсчет идет по `SystemClock.elapsedRealtime()` исключительно во время реального воспроизведения соответствующего сервиса. В Pause, Stop и Buffering время не расходуется. Оба значения сохраняются и могут пережить переход в другую Activity и переключение голосовых движков.

Режим «Конец главы» отдельно хранится для аудиокниги (`audio_sleep_at_chapter_end`) и TTS (`tts_sleep_chapter_end`). Состояние диалога таймера выбирается только из собственной категории, без перекрестного влияния. При достижении главы останавливается только текущая соответствующая сессия.

**Изменение формата настроек:** старый общий дедлайн `audio_sleep_deadline` намеренно больше не используется, потому что он продолжал расходоваться даже без воспроизведения и конфликтовал между режимами. Старые настройки времени нужно выбрать заново один раз после обновления.

### 5. Производительность/диагностика

Метки Edge загружаются вне основного потока. У локального TTS остаётся ранее согласованный кэш меток. Исключена пересборка медиауведомления каждую секунду из фонового аудиотаймера; уведомления обновляются по состоянию. `READER_STARTUP` регистрирует `edge_bind_requested_ms`, `edge_player_bind_ms`, `edge_stream_bind_ms` и отдельные `bind_wait_ms`, а также метрики первоначального кадра и подготовки книги.

## Проверка и ограничения

Включены все регрессионные проверки предыдущих версий, новый JVM-тест монотонных таймеров с имитацией Pause, возобновления, переключения движков и независимого аудиосчётчика, а также статические проверки изменения алгоритмов TTS/оглавления. **Это не Android APK и не тест на устройстве.** Android SDK/Gradle в среде отсутствуют, следовательно визуальную точность WordBoundary, плавность прокрутки и реальное ускорение нужно измерить на телефоне.

HTTP 429 на стороне удаленного Edge WebSocket остаётся возможным; это внешнее ограничение, а не ошибка отрисовки. Версия не заявляет об устранении серверного rate limit.
