# ПРОЧиталка v1.11.161-beta CLEAN — полный перечень изменений

**Исходная версия:** v1.11.160-beta CLEAN Full Source  
**Новая версия:** v1.11.161-beta (`versionCode 16100`)  
**Платформа:** Android Java 17, XML VectorDrawable, minSdk 24.

## 1. Долгое нажатие и выбор текста

- Добавлена отдельная обработка `LONG_PRESS` на текстовой карточке `ReaderActivity` без изменения позиции чтения и без повторного анализа HTML.
- По долгому нажатию выбирается слово; два видимых маркера позволяют расширить выделение на соседние слова, строки и блоки RecyclerView.
- В тематическом плавающем меню **строго четыре пункта, в порядке снимка пользователя**:
  1. **Цвет** — пользовательская цветная подложка.
  2. **Копировать** — копирование выбранного текста в Android Clipboard.
  3. **Заметка** — создание и редактирование заметки с сохранением цитаты.
  4. **Словарь** — настройка слова/фразы Edge TTS без открытия отдельной Activity.
- Иконки получены в виде **четырёх VectorDrawable XML**, геометрия обведена по присланному растровому примеру (не заменены стандартными иконками). Цвет и фон адаптируются к теме приложения, дизайн остальных элементов примера не копируется.
- Меню автоматически располагается рядом с выделением, имеет закруглённые углы и ограничивает ширину экраном; при недостатке места переносится ниже.
- Тап без удерживания сохраняет существующий механизм перехода в режимах Курсор/Озвучка; движение RecyclerView отменяет ожидающее долгое нажатие.
- При завершении перетаскивания маркера меню показывается повторно. Режим RSVP с активным воспроизведением не получает новых управляющих жестов.

## 2. Закладки цвета и заметки

- `ReaderAnnotationsStore.java`: новая SQLite-таблица `annotations`, индекс по книге и диапазону слов, поля цитаты, контекста, цвета, заметки и времени изменения.
- Данные хранятся **отдельно от исходных EPUB/FB2/HTML/TXT**; сам файл книги не переписывается.
- Записи привязаны к каноническому URI `BookUriMigration.legacy()`, чтобы перенос книги в другую папку не разрушал связь с выделениями.
- На экране текстовые подложки накладываются только на уже отображаемые элементы RecyclerView, с использованием `ReadingWordMap`. Примечания подчёркнуты и отмечены небольшим значком на строке.
- В режиме обычного чтения касание отмеченного фрагмента открывает существующую заметку.
- В **Настройки → Чтение → Выделения и заметки** появились четыре настраиваемых цвета и уровень непрозрачности.
- Существующая подсветка активного слова и предложения TTS независима от пользовательских отметок.

## 3. Быстрый словарь

- `EdgeDictionaryRuleDialog.java`: единая форма для `ReaderActivity` и `EdgeDictionaryActivity`.
- Предзаполнение всего выделенного слова или фразы; отдельные поля «Найти» и «Произносить как».
- Выбор ударной гласной, кнопка прослушивания до сохранения, замена, игнорирование, контекстное правило по отдельному переключателю и Regex.
- Лимиты, проверка Regex, сохранение/обновление/удаление продолжают использовать существующий `EdgeDictionaryStore` и его ревизию. База словаря не заменяется.
- Из старого словаря полностью убрана **«Из предложения»** и метод выбора слова из предложения. Прямой переход из читалки в Activity словаря больше не нужен.
- При сохранении словаря пользователь остаётся на прежней позиции в книге. Уже произносимый MP3 не прерывается намеренно.

## 4. Справка по регулярным выражениям

- Вместо прежнего короткого описания раздела «Регулярные выражения словаря Edge TTS» применяется новый `RegexHelp.content()`.
- Описаны: буквальные символы, экранирование, классы, диапазоны, классы Unicode/POSIX, повторения (жадные/ленивые/сверхжадные), границы и якоря, группировки, альтернативы, именованные группы, ссылки `$1`/`${name}`, проверки lookahead/lookbehind, флаги, примеры замены, риск тяжёлых выражений и особенности Java Pattern на Android.
- Текст справки находится в самом приложении и доступен офлайн.

## 5. Edge TTS: 99%, сохранение и HTTP 429

**Что точно показал предоставленный журнал:** при установлении нового WebSocket сервер Edge TTS ответил HTTP 429 два раза; после паузы соединение открылось. Прямой ошибки публикации главы журнал не содержит.

- В `EdgeSpeechQueue` вместо фиксированных 500 мс после HTTP 429 внедрена возрастающая задержка: **60 с, 120 с, 240 с, 480 с, до 15 минут**, с учётом `Retry-After`, если сервер его передал.
- Новые запросы при действующем ограничении не запускаются; текущая очередь и MP3 остаются сохранены.
- В `EdgeChapterArchive` добавлена подробная стадия публикации: получение папки SAF → проверка кэша MP3 → объединение → запись MP3 → запись WordBoundary → повторное чтение MP3 → проверка SHA-256 → запись индекса готовности.
- `publicationError()` передаёт в `EdgeFullBookService` последнюю ошибку вместо прежнего универсального сообщения «Не удалось записать завершённую главу».
- В карточке главы раздела «Загрузка озвучки» появляется действие **«Сохранить»** (если есть фрагменты, но нет подтверждённой готовой главы). Оно повторяет только сохранение уже готовых MP3 и не отправляет запросы на Edge TTS.
- Если части кэша отсутствуют, выводится их количество, а рабочие части не удаляются.
- Глава получает статус 100% только после проверки сохранённого результата.

## 6. Сохранённые функции

Не возвращали автоматическое сканирование, пересборку HTML, хеширование книг или пересчёт позиции при входе в Reader. Остаются импорт HTML-папок, RanobeLIB, MangaLib, сохранение обложек, перенос книг, переименование и мини-игра. Постоянные выделения и заметки не меняют состав книги.

## 8. Проверки и ограничения

Проведены: синтаксический разбор всех Java-исходников, XML-проверка ресурсов, JVM-проверка справки Java Regex, автономные JVM-тесты HTTP 429 и WebSocket-очереди, структурные регрессии v1.11.155–160 и новые проверки v1.11.161.

**Не выполнялись:** полная сборка Gradle/Android SDK и испытание жестов, SQLite, MediaPlayer и SAF на физическом телефоне. Это **исходный проект, не собранный APK**. Истинную причину конкретного отказа SAF можно будет подтвердить по новой диагностике после запуска на устройстве.
