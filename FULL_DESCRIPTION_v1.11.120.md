# ПРОЧиталка v1.11.120-beta CLEAN — ускорение открытия TTS и ленивая подготовка словаря

**Версия:** `versionName 1.11.120-beta`, `versionCode 12000`.
**Основа:** v1.11.119-beta CLEAN. Все согласованные функции предыдущей версии сохранены.
**Тип артефакта:** полный исходный Android-проект, не APK.

## Причина регрессии

В v1.11.119 `EdgeStreamingService.setActive(false)` при выходе из режима TTS завершал сервис. Каждый повторный вход запускал `openBook()`, который затем выполнял `restore()`. Прежний `restore()` проходил **по каждому речевому блоку всей книги**, заново читал настройки произношения, строил карту соответствий слов, рассчитывал хеш MP3, проверял файл и считывал полный JSON-манифест на основном Android-потоке. При этом `savedPercent()` каждые 5 секунд снова обрабатывал словарём весь список речевых блоков — уже на фоне. На книгах большого объёма операции могли значительно задерживать вход в TTS.

## Исправления

1. **Повторный вход без нового каталога.** При выходе из TTS звук останавливается и WebSocket-запросы отменяются, но подготовленная структура книги остаётся в существующем `EdgeStreamingService`. После 120 секунд неактивности сервис может самостоятельно завершиться. При повторном входе в этот интервал `openBook()` узнаёт прежнюю книгу и не перестраивает каталог. Вызов `setActive(true)` снова активирует слушатель.
2. **Ленивая структурная индексация.** `restore()` выполняет только формирование лёгких `Clip` с абсолютными позициями слов. В нём больше нет чтения словаря, `sentences.json`, вычисления MP3-ключей и проверки всех MP3 на диске.
3. **Словарь по требованию.** `prepareClip()` применяет правила замены, игнорирования и произношения только к выбранному фрагменту и к ограниченному числу кандидатов предзагрузки. До этого исходный текст остаётся без изменений. Преобразование производится **перед проверкой MP3-кэша**, потому что ключ зависит от фактически произносимого текста, и используется и для WebSocket и для WordBoundary.
4. **Кэширование обработки.** Ключ/ревизия сохраняются в самом `Clip` для всего срока службы текущего каталога. Полная карта UTF-16 символов и готовый `Result` держатся в LRU-кэше на 20 последних фрагментов. Повторная проверка известного фрагмента не запускает словарь заново, если настройки не изменились. При смене словаря, голоса или скорости пересчитываются только требуемые новые фрагменты, без полного прохода по книге.
5. **Сохранение прежних MP3.** При ленивой записи `sentences.json` прежние строки манифеста с MP3-ключами сохраняются в отдельном IO-потоке, чтобы уже скачанное аудио осталось доступно в разделе загрузок. MP3-файлы не удаляются и не переименовываются.
6. **Обновление прогресса без полного словаря.** `savedPercent()` использует готовые метаданные дискового офлайн-индекса на фоновом исполнителе, вместо вычисления ключей для всей книги.
7. **Общий снимок книги.** `UnifiedBookSession.edgeGroups()` лениво создаёт и запоминает структурные 800-символьные группы Edge TTS. Повторное создание `EdgeStreamingService` в одном процессе использует готовый структурный список без повторного разбора предложений.
8. **Первый фрагмент — приоритет.** Встроенный `pump()` сначала готовит выбранный `Clip` и только потом ближайшие фрагменты, не запуская полный индекс словаря. Сохранены исторические cache keys, пропуск игнорируемых блоков, карты WordBoundary и политика синхронизации озвучки.
9. **Метрики.** В журнал `READER_STARTUP` добавлены `tts_mode_selected`, `tts_ui_ready_ms`, `edge_restore_start`, `edge_restore_end_ms`, `clip_prepare_ms`, `cache`/`stream`-варианты `first_track_ready` и `edge_book_reuse`. Последнее событие фиксируется только однократно для первого готового фрагмента, без дополнительных задач на каждый MP3-пакет.

## Не изменено

- Системный Android TTS, позиция слова и подсветка WordBoundary.
- Просмотр оглавления без изменения позиции воспроизведения.
- Отдельные таймеры сна TTS/аудиокниги, учитывающие фактическое прослушивание.
- Редактор словаря и отдельный список игнорирования.
- Выбор предложения, файловое хранение MP3, Media3 и политика WebSocket.

## Исправление сборки CLEAN FIX1 (тот же versionCode 12000)

- По журналу GitHub Actions задача `:app:compileReleaseJavaWithJavac` завершалась с тремя `illegal forward reference` в `EdgeStreamingService.java:75`.
- Объявление `idleExpiry` перенесено ниже полей `active` и `player`; логика двухминутного освобождения сервиса сохранена без изменений.
- Добавлен `qa/test_edge_idle_expiry_compilation.py`: извлекает **реальный** инициализатор поля из исходника и компилирует его `javac` в малом Java-харнессе с объявлениями, проверяя запрет прямых ссылок на ещё не объявленные поля.
- `versionName=1.11.120-beta`, `versionCode=12000`. Код иных компонентов не менялся.

## Что проверить на устройстве

1. На большой книге переключиться из обычного чтения в Edge TTS пять раз подряд; сравнить `tts_mode_selected -> tts_ui_ready` и события `edge_book_reuse`.
2. Повторить через 3 минуты после выхода из TTS: сервис мог остановиться, но `UnifiedBookSession.edgeGroups` должен сохранить группы до перезапуска процесса.
3. Запустить с готовым MP3 и без него: проверить `first_track_ready source=cache` и `source=stream`.
4. Проверить WordBoundary и overlay при первом воспроизведении, переходах и после изменения словаря.
5. Проверить аудиокнигу, системный TTS и независимые таймеры сна.
