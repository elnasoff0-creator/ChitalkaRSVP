# ПРОЧиталка v1.11.176-beta CLEAN — полная расшифровка изменений

**Основа:** v1.11.175-beta CLEAN Gradle Compile Hotfix. **Версия:** versionCode `17600`, versionName `1.11.176-beta`. Это полный проект Android Java, не подписанный APK.

## 1. Dynamic Version и GitHub Release

В релиз впервые включён `.github/workflows/release.yml`. Текущая версия получена из `app/build.gradle` при сборке, а название публикуемого APK извлекается из **самого APK** с помощью `aapt dump badging`.

* `ChitalkaRSVP-v1.11.176-beta.apk` создаётся автоматически: никакой захардкоженной версии 1.11.58.
* Для запуска на Git-теге проверяется точное соответствие `v${versionName}`; при несовпадении публикация прерывается.
* Перед публикацией APK выравнивается и подписывается `zipalign` / `apksigner` по существующим secrets; подпись проверяется, SHA-256 записывается в `SHA256SUMS.txt`.
* В существующем релизе удаляются только старые по имени APK, файлы других типов сохраняются, новая сборка и контрольная сумма обновляются.
* Бета-версии публикуются как prerelease. Версия, показываемая приложением в настройках, по-прежнему читается из PackageManager.

## 2. Устранение долгого переключения Play → Pause

`UnifiedDownloadManagerActivity` теперь меняет значок сразу после касания: `STARTING` и `PAUSING` отображаются до завершения команды, `QUEUED` обозначает принятую команду, `PAUSED` — паузу. Ошибка приводит к возврату исходного состояния и тексту причины.

`DownloadCommandController` содержит одну последовательную фоновую очередь команд и `commandGeneration`. При быстром Play/Pause/Play устаревшее подтверждение не может заменить более новое намерение. Прежняя задержка `postDelayed(this::reload,450)` из основного обработчика удалена. Подготовка очередей MangaLib, RanobeLIB и Ranobes не выполняется в UI-потоке менеджера.

Дополнительно облегчены `DownloadWorker`, `DirectLinkDownloadService` и `EdgeFullBookService`: их тяжёлые операции чтения/записи очередей вынесены из `onStartCommand`; первый вызов `startForeground` выполняется вовремя. В сервисе аудиокниг появилась последовательная очередь разных книг: Play второй книги не теряется, пока работает первая, а Pause книги в очереди не останавливает активную чужую книгу.

## 3. Адресные события и отсутствие полного перечитывания

Расширен `DownloadChangeBus`: типизированные `CHAPTER_PROGRESS`, `CHAPTER_COMMITTED`, `COMMAND_STATE`, события имеют ID произведения, точный ID главы, последовательность и состояние. Старый `publish(id)` сохранён для структурных изменений и совместимости с прежними экранами.

`UnifiedDownloadManagerActivity` по прогрессу больше не вызывает `reload()`, `readRows()`, `buildInfo()` или SAF. Существующий `RecyclerView.FileAdapter` хранит индекс `chapterKey -> position`, поэтому меняет только нужную строку с `PAYLOAD_PROGRESS`, а также верхнюю шкалу и счётчик. В основном экране загрузок используется обновление конкретной карточки с payload `fast-progress`, без повторного поиска всех глав.

Процентные события объединяются по произведению/главе, максимум приблизительно каждые **225 мс** на видимом экране. Финальные commit-события отправляются без ожидания очередного периодического обновления.

## 4. Быстрый общий прогресс и восстановление

Новый `DownloadProgressTracker.java` хранит карту глав и общий агрегат в оперативной памяти. При изменении одной главы корректируется только её вклад: `done += newPermille - oldPermille`, без O(N)-обхода очереди. Полный план глав строится только при открытии либо изменении состава. События с устаревшей последовательностью отбрасываются; 100% и галочка возникают только после подтверждения устойчивой записи, а не по достижении сетевого прогресса.

Новый `DownloadProgressStore.java` записывает через Android `AtomicFile` малый локальный JSON: ID, ревизию, число и количество готовых глав, общий прогресс, текущую главу. Запись идёт через один общий IO-исполнитель с коалесцированием примерно **раз в 4 с**, а при завершении главы — сразу в фоне. Полный список глав/файлы MP3/WordBoundary в JSON не дублируются. После перезапуска быстрый снимок показывается **как предварительный** и заменяется реальными данными очереди при фоновой сверке.

## 5. Изменения конкретных загрузчиков

* **Аудиокниги:** `DownloadWorker` передаёт прогресс активного файла и отдельный commit после SAF-публикации; фоновая очередь допускает несколько произведений, но только один активный network worker.
* **MangaLib:** `MangaLibStorage.progress` посылает текущую страницу/число страниц; `MangaLibQueue` запускает/ставит на паузу серии пакетно через один `MangaLibStorage.putAll`, вместо множества `SharedPreferences.commit()` по одной главе.
* **Edge TTS:** сервис после синтеза сообщает адресный прогресс главы; после подтверждённой публикации MP3-фрагментов с WordBoundary отправляет commit. Другая готовая глава не требует общего сканирования.
* **RanobeLIB / Ranobes:** фиксируется событие подтверждённой готовности отдельной HTML-главы; внутренний процент загрузки HTML не выдумывается.
* **Скачать по ссылке:** промежуточный прогресс каждого файла передаётся без общей записи всего JSON каждые 650 мс; устойчивые контрольные точки — примерно раз в 3,5 с и по завершении.

## 6. Совместимость и сохранение функций

Не изменены форматы сохранённых глав, оригинальные MP3 и WordBoundary, файлы манги/комиксов, содержимое аудиотеки, сохранённые книги и пользовательские темы. Сохранены вся механика рыбалки, свайп в архив **вправо**, галочки готовых глав, оптимизированная лента, плеер и поиск. Переключение папки не переносит/не удаляет существующие файлы.

## 7. Что новая версия не гарантирует автоматически

`AtomicFile` содержит **предварительную** сводку для UI, а не подтверждение физической сохранности файлов. Полные SAF-проверки в случае ошибок или изменения папки остаются доступны. Для незапущенного на реальном Android приложения нельзя гарантировать отсутствие визуальных гонок и ANR без инструментальных тестов.

Ограничения: не каждый источник имеет достоверный общий byte-total; для RanobeLIB/Ranobes промежуточный процент главы не рассчитывается. Legacy-слушатели на некоторых старых экранах всё ещё используют структурный `publish` при устойчивых контрольных точках. Не все операции архива Edge TTS переведены на независимые per-book locks, чтобы не нарушать совместимость.

## 8. Проверки и приёмка

Запустить `sh qa/check_v176.sh`, затем обязательно полную CI-сборку `gradle --no-daemon :app:assembleRelease --stacktrace --console=plain`. На Android проверить запуск/паузу двух книг, 500 глав и 1000 событий, отсутствие ложных 100%, восстановление после force-stop, отсутствие сети, ошибки SAF, внешние USB/SD хранилища, все шесть источников и быстрые повторные нажатия.

**Статус:** исходный релиз-кандидат; Android SDK и Gradle недоступны в среде локальной подготовки, полная сборка APK и UI-тесты на устройстве **не подтверждены**.
